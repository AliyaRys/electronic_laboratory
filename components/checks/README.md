# Компоненты сверки данных

`CheckUi.js` — общий runtime-источник для экранов сверки и Storybook. Он не зависит от фреймворка и доступен как `globalThis.VseCheck`.

## Публичные функции

- `createSectionHeader` — заголовок раздела с семантически закреплённой иконкой, описанием и необязательной стоимостью.
- `createComparisonActions` — пара действий «соответствует / не соответствует».
- `createComparisonField` — проверяемое значение, результат и фактическое значение при расхождении; `factOptions` переключает фактическое значение на закрытый список вариантов.
- `createProductTaxonomyFields` — четыре связанных проверяемых поля классификации продукции: тип, продукция, вид и название.
- `mountProductTaxonomies` — преобразует слот `data-product-taxonomy` в поля классификации; значения передаются через `data-product-type`, `data-product`, `data-product-kind` и `data-product-name`.
- `appendMismatchReason` и `mountMismatchReasons` — добавляют обязательную причину расхождения к отдельным строкам с `data-mismatch-reason` или к перечисленным в `data-mismatch-reason-fields` названиям полей формы.
- `validateMismatchDetails` — проверяет фактическое значение и причину у отмеченных расхождений и переводит фокус на первое незаполненное поле.
- `createCompositionTable` — состав партии с произвольным набором столбцов для мяса, молока и будущих видов продукции.
- `createTransportObservation` — нативный одиночный список для фактического состояния перевозки.
- `createDecisionField` — нейтральное обязательное или необязательное решение, которое не является оценкой соответствия.
- `createRepeatVseDecision` — закреплённое решение о необходимости повторной ВСЭ после осмотра продукции и транспорта. При выборе «Требуется повторная ВСЭ» появляются обязательные поля «Основание для проведения повторного ВСЭ» и «№ акта»; при «не требуется» они скрываются и очищаются. `validateRepeatVseDetails` проверяет заполнение обоих полей и возвращает объект с сообщением и полем для фокуса.
- `createInvoiceWaiver` — необязательный чекбокс «Ярмарка» в расчёте стоимости услуг: сверка данных и ВСЭ по партии проводятся без оплаты. `bindInvoiceWaiver` отмечает активное состояние; страницы сами пересчитывают итог при включении.
- `createTransactionDecision` — вопрос «По партии будет произведена транзакция» (Да/Нет). При ответе «Да» появляется обязательное поле «Тип транзакции» с вариантами «Внутренняя» и «Внешняя»; при «Нет» поле скрывается и очищается. Подключается к блоку результатов сверки через слот `data-check-results` с атрибутом `data-transaction="true"`. `validateTransactionDecision` проверяет оба ответа и возвращает объект с сообщением и полем для фокуса.
- `createReceiptDecision` — обязательный выбор способа завершения приёмки. Параметр `automaticAct` оставляет три решения: полное гашение, частичное гашение и полный возврат; необходимость акта рассчитывается отдельно.
- `evaluateReceiptDecisions` и `updateReceiptDecision` — единая матрица доступности решений по заполненным сравнениям; допустимое расхождение веса для полного гашения без акта составляет не более 5%.
- `validateReceiptDecision` и `getReceiptDecisionPayload` — проверка дополнительных данных частичного гашения/возврата и получение нормализованного решения для экранного сценария.
- `createSpecialistField` — неизменяемое поле активного специалиста Госветслужбы.
- `createCheckResultsSection` — общий блок результатов сверки со специалистом и решением о приёмке. Решение о повторной ВСЭ включено по умолчанию; для партии без ранее проведённой ВСЭ используйте `includeRepeatVse: false` или `data-repeat-vse="false"` в слоте `[data-check-results]`.
- `createResearchResult` — результат одного исследования в интерфейсах, где результаты формируются самой лабораторией.
- `createInvoice` — расчёт стоимости услуг.
- `createSection` — составной блок, который собирается из перечисленных компонентов.

Нативный `select` в состоянии перевозки выбран осознанно: открытое меню может оставаться системным. Компонент владеет закрытым полем, стрелкой, семантической подсветкой и доступным именем.

Блок `Результаты сверки` размещается перед расчётом стоимости. Имя специалиста автоматически берётся из активного пользователя и показывается в неизменяемом поле. Решение о приёмке пользователь всегда выбирает явно; система только блокирует несовместимые варианты и объясняет причину. Для частичного гашения вводятся доставленный, принятый и возвращаемый объёмы и причина возврата. Решение о повторной ВСЭ также обязательно, но само по себе не меняет сценарий гашения или отказа от партии.

До завершения всех сравнений мясные экраны не выводят четыре одинаковых пояснения о незаполненной сверке: поле решения остаётся недоступным само по себе. После заполнения показываются только актуальные ограничения в формате «Вариант недоступен: причина».

Мясные сверки включают у формы `data-receipt-auto-act="true"` и `data-receipt-reason-catalog="meat"`. Первый признак оставляет в списке три решения и автоматически показывает плашку акта для полного или частичного гашения. Второй подключает коды `MEAT_RETURN_REASONS`, при этом пользователь видит только русские названия. При выборе «Другая причина» открывается обязательное текстовое поле длиной не более 240 символов.

Длинное заключение ранее проведённой ВСЭ выводится через `globalThis.VsePriorConclusion`. Компонент `PriorConclusion.js` создаёт нативный `details`: в закрытом состоянии показывает однострочный фрагмент, в открытом — полный текст. Страницы подключают `prior-conclusion.css` и размещают слот `data-prior-conclusion` с текстом в `data-text`; `mountAll()` заменяет слот общим компонентом.

HTML-макеты подключают `check-ui.css` и `CheckUi.js`; Storybook импортирует те же файлы через `story-support.js`.

`check-ui.css` также задаёт общую геометрию окон решения по партии: отказа, полного и частичного гашения. Оболочка `.extinguish-modal` всегда ограничена высотой визуального окна браузера, заголовок и действия остаются на месте, а длинное содержимое прокручивается внутри `.modal-body`.

Иконки принадлежат `components/icons/VseIcon.js`. Параметр `section` принимает только ключ из канонической карты разделов; произвольный SVG в заголовок не передаётся. Карта и правила использования описаны в `components/icons/README.md`.
