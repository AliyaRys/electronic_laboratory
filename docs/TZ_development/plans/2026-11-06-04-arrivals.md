# Поступления и сверка Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать локальные очереди и сохранённую сверку с безопасной границей внешнего подтверждения.

**Architecture:** arrivals хранит внешний снимок отдельно от местных фактов. Получение/гашение пока выключены; ReceiptEvidenceReader и confirm_receipt определены сейчас для тестирования downstream без SOAP.

**Tech Stack:** SPEC-03, PostgreSQL constraints, Decimal, React Query/RHF.

**Spec:** DATA-02/06, API-04, все CHK field-mapping; ФТ 02/13 и ADR-015–019. Зависит I/F/C.

## Global Constraints

- «Один входящий транспортный эВСД» — одна партия; UNIQUE(contour, evsd_uuid).
- «Исходные и фактические значения хранятся раздельно».
- «Границы ±5% включены»; недостача не является обратным грузом.
- Без подтверждённой приёмки ВСЭ/заключение недоступны; никаких production fake confirmations.
- Входящий `batch.product` содержит GUID/UUID продукции второго уровня без названия. `IncomingView` разрешает его через локальный `mercury_product_guid_lvl_2`; сетевой запрос ProductService на каждое чтение и показ сырого GUID пользователю запрещены.
- `batch.product`, `batch.subProduct` и `batch.productItem` сохраняются как разные уровни классификации. `productItem.name` — номенклатура производителя четвёртого уровня и не подменяет название продукции второго уровня.
