# Физические пробы Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать самостоятельный физический учёт проб и неизменяемую утилизацию всего остатка.

**Architecture:** samples хранит отбор независимо от ВСЭ; одна корзина lab/species сериализует изменение остатка. apply_sample вызывается координатором сохранения ВСЭ без собственного commit.

**Tech Stack:** PostgreSQL locks, Decimal, FastAPI, React.

**Spec:** DATA-03, API-06, ФТ 05, O-01/02/04/05/07, ADR-016/017/023. Зависит A/C/I/F; пользовательское создание отбора появится в E01.

## Global Constraints

- «Только весь остаток, вес подставляется из учёта».
- «Исправления и отмена утилизации в MVP не нужны».
- «Новая ВСЭ по той же партии по умолчанию использует прежний отбор без повторного начисления».
- Группировка по «Вид продукции» Меркурия; масса партии не уменьшается на пробу.

## Review Focus

- Удаление ВСЭ и позднейшее пересоздание: S01 сохраняет идентичность отбора.
- REUSE утилизированного: S01 отказывает, требует NEW.
- Коррекция 0,8→0,6: S01 меняет остаток на−0,2 ровно один раз.
- Новый отбор при открытом списании: S02 отклоняет старую ревизию.
- Фильтр периода истории: S03 не уменьшает текущий balance.
