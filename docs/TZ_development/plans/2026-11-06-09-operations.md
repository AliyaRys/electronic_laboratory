# Эксплуатация и поставка Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Доказать сохранность данных, производительность и воспроизводимость выпуска локальных модулей.

**Architecture:** Собственный Linux Compose app-хост, отдельные backup и runner/registry. Удаление ВСЭ подтверждается синхронным remote-flush WAL, остальные записи используют local commit.

**Tech Stack:** PostgreSQL18.6 tools, nginx TLS, Compose, GitVerse CI/CD, Distribution3.1.2.

**Spec:** SPEC, inputs OPS-01, ADR-011–014/023/024, E03 durability. Зависит I–R, ВетИС read/write остаются false.

## Global Constraints

- «RPO≤15 минут, RTO≤4 часов» для обычных записей/потери app-хоста при исправном backup и ключах.
- Подтверждённый DELETE: RPO=0 при потере одного app-хоста; без durability readiness нет успешного удаления.
- «100 лабораторий, 500 зарегистрированных сотрудников, 100 одновременно активных»; «5 000 новых поступлений в сутки».
- «p95 чтения страниц ≤2 секунд, локального сохранения ≤3 секунд»; ошибки<1%; 5-вет≤60 сек.
- Никакого автоматического production deploy произвольного main-коммита; текущая задача подготовки документации ничего не развёртывает.

## Review Focus

- App-хост потерян сразу после успешного DELETE: O02 не возвращает удалённую карточку.
- Backup receiver оборван во время commit: O02 UNKNOWN вместо ложного успеха/отказа.
- Восстановленная outbox содержит SUBMITTING: O02 запрещает повтор внешнего submit.
- Недоверенный PR: O01 не получает registry/deploy secrets.
-100000 ВСЭ в payload32MiB: O03 измеряет размер/память/задержку без полных протоколов.
