# ВетИС: получение входящих Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Последним блоком подключить разрешённое получение входящих транспортных эВСД из тестового профиля ВУ, сохраняя source `name` и импортируя в мясной MVP только `productType=1`.

**Architecture:** Изолированный Zeep adapter реализует ports DATA-06; PostgreSQL outbox и arq worker того же backend image. Планировщик каждые 15 минут запускает полный read-проход для Агропромышленного парка от выделенной тестовой read-идентичности; кнопка «Обновить» ставит тот же идемпотентный job. Общий product dictionary не участвует в отображении: нормализатор сохраняет GUID/UUID/name каждого уровня из source XML.

**Tech Stack:** Zeep4.3.3, SOAP ВУ, arq/Redis, PostgreSQL.

**Spec:** O-12, [контракт тестового Меркурия](mercury-test-integration-contract.md), API-04/10, DATA-02/05/06, INPUT-01, ADR-018. Зависит O01–03 и локальных модулей.

## Global Constraints

- «Только ветеринарные управления, mercury-vu.service; нет fallback на сервис ХС».
- На этапе V01/V02 выполняется только чтение тестового контура, `VETIS_WRITE_ENABLED=false`. Это ограничение этапа и действий агента; W01–W03 обязаны реализовать рабочий enabled write-state по O-13.
- Автоматическое чтение каждые 15 минут обязательно; интеграционная идентичность имеет только read-capability и отделена от личного инициатора будущего гашения.
- Подтверждены endpoint/serviceId/namespace из успешного примера, но V01 всё равно закрепляет WSDL/XSD imports и checksums до включения read.
- `GetVetDocumentList` не имеет server-side productType filter: после scoped `INCOMING+CONFIRMED` нормализатор локально оставляет только `batch.productType=1`.
- Source `name` каждого уровня хранится вместе с GUID/UUID. `mercury_product_guid_lvl_2` больше не является источником UI-названия; промах таблицы не блокирует import при наличии source `name`.
- Credentials и сырой `API REQUESTS.txt` не входят в Git/fixtures/logs; тестовые fixtures обезличены.

## Review Focus

- Несколько страниц с повторённым UUID: V01 не создаёт дубликат.
- Сбой на последней странице: V02 не передвигает successful checkpoint.
- Отозваны права между страницами: V02 прекращает следующие SOAP-заявки.
- INCOMING без транспортного происхождения: V01 не импортирует посторонний документ.
- Неоднозначная лаборатория для площадки: V01 диагностирует, не дублирует партию.
