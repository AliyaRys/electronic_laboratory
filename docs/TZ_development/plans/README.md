# Технические задания: Электронная лаборатория ВСЭ

Редакция 1.0 от 06.11.2026. Результат этой работы — документация для разработки мясного MVP, не реализация приложения. Основание: ADR 1.1, ФТ v2.0, O-01–09 и подтверждённые R-01–09. Подготовлено по Superpowers 7.0.1 writing-plans.

## Как передать работу агенту

Передавайте агенту весь репозиторий, этот README, общие приложения и **один** план из таблицы. Одного текста отдельного задания без зависимостей недостаточно. Сначала агент читает указанные ФТ/ADR, затем проверяет фактически выполненные предыдущие задания. Успешная сборка макетов не означает готовности backend или интеграции.

Готовая инструкция:

> Реализуй только выданный план из docs/superpowers/plans. Прочитай README, specification.md, data-contract.md, api-contract.md, field-mapping.md и его исходные ФТ/ADR. Выполняй задачи с проверками по порядку; отмечай выполненные шаги только после проверки. Сохрани чужие незавершённые изменения. Не расширяй MVP, не меняй архитектуру и бизнес-правила. Если зависимость не готова, укажи конкретный отсутствующий контракт; не заменяй её демонстрационным успехом. В конце приложи изменённые файлы, команды и результаты проверок, ограничения и остаток работ. Реальный deploy выполняй только по отдельному поручению.

Порядок сознательно ставит пробы перед ВСЭ: пробный отбор вызывается в транзакции сохранения ВСЭ, поэтому контракт учёта должен существовать первым. До 06 отборы для проверок создаются только тестовыми фикстурами, пользовательский автономный отбор вне ВСЭ не добавляется.

**ВетИС реализуется последним.** Этап 10 подключает разрешённое чтение непосредственно к production, потому что нужный метод тестового контура не работает. Этап 11 проверяет write-контракт только на fixtures/локальном симуляторе без production write credentials. Production не получает endpoint «считать принятым» и не выполняет гашение/возврат ради теста. Этап 11 не означает готовность живого полного маршрута; она остаётся закрыта до отдельного письменного решения владельца и нового плана ввода.

## Сдача каждого задания

Каждая задача — отдельный цикл failing test → минимальная реализация → passing test → просмотр diff → адресный commit только своих файлов, если фиксация разрешена в сессии исполнения. Не коммитить весь рабочий каталог: в исходном состоянии есть многочисленные изменения пользователя. Команды в планах относятся к **будущему** приложению; сейчас backend/ и frontend/ ещё отсутствуют. Программный код этой документационной задачей не создаётся. Способ исполнения выбирается при передаче задания; текущий запрос не запускает разработку.
