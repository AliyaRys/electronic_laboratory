# Адресная приёмка SC/AT

Все 101 SC и 25 AT включены индивидуально. Исходный сценарий применяется с O-01–12: нет сохраняемого черновика; физическая проба/утилизация сохраняются при удалении ВСЭ; повторное использование не начисляет отбор; поздняя правка только итог; списание всего остатка; врач в «Отчётах» видит только пробы; ВетИС читается из test profile с `productType=1` и source `name`. Старый текст SC не отменяет эти уточнения.

**Обязательное ограничение O-12:** тестовый ВетИС используется только для чтения входящих эВСД. Любой SC/AT с гашением, частичной приёмкой или возвратом проверяется обезличенными fixtures/локальным симулятором и не является разрешением на внешний write. Живой write-кейс получает статус `Не выполнялся — запрещено O-12`, а не запускается ради закрытия чек-листа. Зелёные contract/e2e-тесты и test credentials не меняют `VETIS_WRITE_ENABLED=false`.

При этом write-контракт не считается проработанным частично: приёмка должна покрыть XML preview из закреплённого raw XML/checksum и сверки, все шесть сочетаний соответствие/несоответствие × три решения, независимый результат ветосмотра, submit/poll/reconcile/UNKNOWN, устаревшую внешнюю версию и отказ без owner authorization. В offline-тесте authorization выпускает только специальный fake issuer; приложение, администратор, seed и миграция не имеют способа создать его.

Каждая строка — обязательный приёмочный кейс владельца указанной задачи. Исполнитель добавляет автоматизированный тест с ID в имени (`test_sc_001`, `test_at_01`) либо адресный ручной протокол в docs/implementation/<plan-id>-evidence.md с шагами, данными и результатом. Ручная проверка допустима для геометрии формы/реального внешнего допуска; конкуренция, транзакции, область и арифметика автоматизируются. Fixture-based integration не доказывает реальное ВУ. Ни один статус не заявлен passed этой документацией.

## Технические проверки сверх SC/AT

I02: cross-worker revoke/CSRF/Redis failure; I03: concurrent last-admin/duplicate login. A02: exact ±5%/нулевой document mass; S02: concurrent disposal/new collection; E01: all-or-nothing и lost response; E02: lock crossing midnight; E03/O02: remote-flush loss/restore. R02: token tampering/other session/key rotation/100k payload. D02: malicious text/render failure/cyrillic A4. V02: full pagination failure/checkpoint/revocation. W02: lost applicationId/lease/UNKNOWN/manual evidence. O03: measurable capacity/latency/retention/no secrets. Тесты закреплены в задачах-владельцах.
