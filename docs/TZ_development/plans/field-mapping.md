# Все 82 поля: DTO, хранение и проверка

Исходное название и обязательность — ФТ 10, которое передаётся исполнителю целиком. Здесь конкретные property names для typed schemas. CHK source нормализуется ВУ-adapter; фактические XML XPath/namespace заполняются только V01/W01 по выданному manifest в docs/integration/chk-xml-mapping.md. Ни один неподтверждённый XPath не выдан за факт. Справочники заболеваний/варки/возврата берутся дословно из ФТ 10; иной текст требует свободного поля.

`checks[CHK-ID]` = Comparison API-04; source поля не принимаются в write. product.* = четыре ID/name пары, sender/receiver = enterprise/owner ID/name пары; не дополнительные поля адреса. Неназванная новая бизнес-сущность не добавляется. VSE-F06–09 в исходной таблице имеют группу и отдельное название, обе части сохранены в source каталоге.

## Поведение write и read

Все source поля доступны в IncomingView/ExaminationView только для чтения. ReconciliationWrite хранит Comparison по field ID; inspection/decision/repeat/transaction/fair имеют typed свойства API-04. ExaminationWrite хранит research по stable indicator_id; read view достраивает readonly party/author/time/costs. Часть VSE полей имеет иной write/read путь: sample.mass/date write внутри NEW/EDIT selection, read из выбранного самостоятельного отбора; REUSE содержит только collection_id. Производная плашка акта/стоимость/status не принимаются от клиента. errors содержит фактический JSON path и исходный field_id.
