# Чек-лист распределения задач: GLM — основной исполнитель

Редакция 2 от 06.11.2026. **24 задачи — GLM, 7 самых сложных — GPT-5.6 Sol.** Это примерно 77% и 23% по числу задач, а не оценка доли времени или стоимости. Порядок и критерии готовности исходных ТЗ сохраняются.

GLM выполняет полноценные задачи frontend, backend, расчётов, поставки и получения данных ВетИС. GPT используется для семи участков, где одновременно действуют несколько сложных условий: права, атомарность, необратимость, потеря ответа или аварийное восстановление. Постоянная проверка каждой задачи GLM через GPT не требуется.

Это распределение работ под предпочтение владельца и предположение «GLM слабее GPT», а не результат сравнительного испытания конкретных версий моделей. Высокая сложность задачи GLM не исчезает: она компенсируется подробным ТЗ, небольшими последовательными изменениями и обязательными проверками.

## Как выдавать задачи GLM

- [ ] Передать ровно одну задачу с полным исходным ТЗ, README и нужными общими контрактами. Для большой задачи разбить её на изменения по файлам/сценариям, сохраняя общий критерий сдачи.
- [ ] Убедиться, что предыдущие зависимости действительно готовы. Если зависимость делает другая модель, передать сведения о её изменениях и тестах.
- [ ] Поручить реализовать весь объём задачи: код, миграции при необходимости, тесты, экранные состояния и документацию. GLM не ограничивается вёрсткой.
- [ ] Требовать адресный список изменённых файлов, выполненные команды и их результаты. Для UI — проверку страницы и скриншоты, для PDF/Excel — проверку настоящих файлов, для БД — реальные PostgreSQL-тесты.
- [ ] Не разрешать менять ФТ, архитектуру, обязательные тестовые ожидания и ограничения ради прохождения сборки.
- [ ] Проверить предусмотренные ТЗ границы и отказы: чужой контекст, двойное действие, устаревшая ревизия, потерянный ответ, нулевые/пустые значения и границы дат — где применимо.
- [ ] Отмечать задачу после выполнения применимых критериев. Постоянный GPT-review для сдачи каждой GLM-задачи не требуется.

Если конкретный сбой не удаётся устранить после двух содержательных попыток, передать GPT узкую проблему: тест, ошибку, затронутый контракт и уже проверенные варианты. Это способ разобрать действительно сложный случай, а не автоматическая передача всего модуля. Недоступные внешние данные или credentials модель не выдумывает: зависимая проверка остаётся невыполненной с конкретной причиной.

## Что именно изменилось

Распределение заменяет прежнюю схему «5 задач GLM, 26 GPT» на **24 GLM и 7 GPT**. GLM получает также backend, расчёты, инфраструктуру и read-интеграцию. Обязательная проверка GPT после каждой задачи снята. Исходные требования и критерии приёмки не ослаблены; высокая сложность GLM-задачи не переименована в лёгкую ради нового распределения.
