# ТЗ 12. Отчёты: форма 5-вет (раздел III)

Дата: 02.11.2026. Статус: требования к HTML-макетам согласованы; расчёт отдельных показателей требует подтверждения ветеринаров до подключения реальных данных.

Общие правила административных экранов заданы в [README](README.md). Этот документ описывает новый раздел администратора «Отчёты», создание и просмотр неизменяемого отчёта по форме 5-вет (раздел III), а также отдельное представление для печати и PDF.

## 1. Цель и границы MVP

Администратор выбирает лабораторию и завершённое полугодие, формирует отчёт из сохранённых карточек ВСЭ мяса, вручную заполняет семь классификационных кодов и сохраняет неизменяемый снимок отчёта.

В MVP:

- доступен один тип: «Отчёт по форме 5-вет (раздел III)»;
- отчёт строится только по карточкам ВСЭ мяса и продуктов убоя;
- один отчёт соответствует одной лаборатории и одному завершённому полугодию;
- черновиков, автосохранения, редактирования сохранённого отчёта и ручной корректировки рассчитанных ячеек нет;
- после сохранения доступны просмотр, Excel, PDF, печать и удаление;
- реальная генерация файлов и серверный расчёт не входят в создание макетов, но их интерфейсные состояния входят.

Раздел проектируется расширяемым: позднее в селекторе появятся другие формы отчётности. Не добавлять их фиктивные пункты сейчас.

## 2. Источник формы

Исходный образец — книга `отчет 5 вет раздел 3.xlsx`, предоставленная владельцем продукта. В ней два смысловых блока:

- лист «шапка»: наименование и адрес организации, семь классификационных кодов;
- лист «отчет»: официальная матрица раздела III, строки 166–242 и колонки по видам животных.

Формулировки показателей, номера строк и порядок колонок в макете не сокращать и не переименовывать. Макет не является новой редакцией официальной формы.

## 3. Навигация и доступ

В административной конфигурации общей шапки добавить пункт «Отчёты» сразу справа от «Управление пользователями».

- Использовать только `components/shell/AppHeader.js` и его API.
- Активный ключ раздела: `reports`.
- Для пункта использовать общий ключ иконки `admin-reports`; рекомендуемый источник — Lucide `file-spreadsheet`.
- Иконку сначала добавить в общий реестр и Storybook, затем использовать в шапке. Локальный SVG на странице запрещён.
- Геометрия и интервалы шапки не меняются.
- Раздел доступен всем административным учётным записям; отдельного разрешения для отчётов в MVP нет.
- Рабочим пользователям раздел недоступен. Будущий сервер обязан проверять административный доступ на чтение, создание, экспорт и удаление.

## 4. Состав макетов

| Макет | Предлагаемый файл | Назначение |
| --- | --- | --- |
| Список отчётов | `admin-reports.html` | Поиск, фильтры, таблица сохранённых отчётов, создание и действия |
| Создание отчёта | `admin-report-create.html` | Выбор параметров, формирование предварительного отчёта, ввод кодов, сохранение |
| Просмотр отчёта | `admin-report-view.html` | Неизменяемый сохранённый отчёт и действия с ним |
| Печать / PDF | `admin-report-print.html` | Отдельное чистое представление официальной формы без интерфейса системы |

Excel — выгружаемый файл, отдельный HTML-макет для него не нужен. Диалоги удаления, предупреждения о потере данных и технические состояния являются состояниями перечисленных экранов, а не новыми страницами.

## 5. Общая модель отчёта

Сохранённая запись содержит как минимум:

- стабильный `id`;
- тип отчёта;
- `laboratoryId`, сохранённые наименование и адрес лаборатории;
- год и номер полугодия;
- начало и конец периода;
- дату и время формирования в `Europe/Moscow`;
- количество вошедших сохранённых карточек ВСЭ;
- семь введённых классификационных кодов;
- рассчитанную матрицу формы;
- версию правил расчёта;
- техническую версию записи.

Отчёт — неизменяемый снимок. При нажатии «Сформировать отчёт» набор исходных карточек и рассчитанная матрица фиксируются для предварительного просмотра. «Сохранить отчёт» сохраняет именно показанный снимок вместе с введёнными кодами. После сохранения позднейшие изменения карточек ВСЭ не меняют отчёт.

Уникальность: одновременно может существовать только один отчёт одного типа для сочетания «лаборатория + год + полугодие». Проверка нужна при выборе периода, формировании и сохранении; будущий сервер обеспечивает её атомарно.

## 6. Экран списка отчётов

### 6.1. Верхняя область

- Заголовок: «Отчёты».
- Краткое описание: «Формирование и хранение регламентированной отчётности лабораторий.»
- Справа основная кнопка «Создать отчёт».
- Ниже поле «Тип отчёта» с единственным значением «Отчёт по форме 5-вет (раздел III)».

Селектор типа остаётся видимым, несмотря на один вариант: он задаёт архитектуру будущего раздела. Не показывать пустое раскрывающееся меню и не добавлять недоступные будущие отчёты.

### 6.2. Поиск, фильтры и сортировка

- поиск по наименованию лаборатории;
- «Год»;
- «Полугодие»: «Все», «I полугодие», «II полугодие»;
- «Сортировка»: по дате формирования, по умолчанию сначала новые;
- действие «Сбросить» появляется при изменённых условиях.

В HTML-макете фильтрация может выполняться по демонстрационному набору. Будущий удалённый поиск — с задержкой 300 мс. Состояние списка хранить по общему административному контракту на время перехода «список → отчёт → список». При изменении фильтра или поиска переходить на первую страницу.

### 6.3. Таблица

Колонки:

1. «Отчётное полугодие»;
2. «Лаборатория»;
3. «Количество проведённых ВСЭ»;
4. «Дата и время формирования»;
5. «Действия».

Форматы:

- период: `I полугодие 2026`;
- дата: `15.07.2026 10:24`;
- количество ВСЭ: целое число без единицы в ячейке.

В этом списке количество означает число сохранённых карточек ВСЭ, вошедших в отчёт. Это не утверждает методику расчёта строки 166 официальной формы.

Вся строка открывает сохранённый отчёт. Реализовать это семантически доступной основной ссылкой, а не `onclick` на `tr`: строка открывается с клавиатуры, имеет понятный фокус. Кнопка действий и пункты меню не запускают переход строки.

В колонке действий одна кнопка с тремя точками и доступным именем/подсказкой «Действия». Меню содержит:

1. «Посмотреть»;
2. «Скачать Excel»;
3. «Скачать PDF»;
4. «Распечатать»;
5. «Удалить» — визуально опасное действие.

Меню закрывается по Escape, клику снаружи и после выбора; фокус возвращается на кнопку. У нижних строк оно раскрывается вверх, если снизу недостаточно места, и не обрезается таблицей.

### 6.4. Пагинация

- 20 записей на страницу;
- текст диапазона и общего количества, например «1–20 из 47»;
- кнопки «Назад» и «Вперёд»;
- после удаления последней записи текущей страницы номер страницы уменьшается до существующего.

Для проверки макета использовать не менее 25 синтетических записей.

### 6.5. Состояния списка

- загрузка: стабильный каркас таблицы, без скачка ширины;
- общая ошибка: «Не удалось загрузить отчёты» и «Повторить»;
- отчётов ещё нет: объяснение и кнопка «Создать отчёт»;
- по фильтрам ничего не найдено: «Отчёты не найдены» и «Сбросить фильтры»;
- загрузка экспорта: выбранный пункт временно занят, повторный запуск блокирован;
- ошибка экспорта/печати: доступное сообщение с повтором.

## 7. Создание отчёта

Экран имеет два последовательных состояния на одной странице.

### 7.1. Шаг 1 — параметры

Поля:

- «Лаборатория» — обязательный выбор из демонстрационного справочника лабораторий;
- «Отчётное полугодие» — обязательный выбор из завершённых полугодий, для которых у выбранной лаборатории ещё нет сохранённого отчёта.

По умолчанию выбирается последнее завершённое доступное полугодие. Например, начиная с 1 июля 2026 года доступно I полугодие 2026; II полугодие 2026 не доступно до 1 января 2027 года.

Список лабораторий в макете — отдельная синтетическая фикстура. Не выводить его из списка пользователей: источник лабораторий является будущим контрактом справочника.

Основная кнопка: «Сформировать отчёт».

Проверки до формирования:

- период завершён;
- отчёта для сочетания ещё нет;
- за период есть хотя бы одна сохранённая карточка ВСЭ мяса;
- черновики и незавершённые ВСЭ не учитываются.

Если данных нет, не создавать пустой отчёт и показать: «Нет данных для формирования отчёта». Если все завершённые периоды уже заняты, объяснить это рядом с селектором.

Во время расчёта кнопка показывает «Формируем…», сохраняет ширину и не допускает повторного запуска. Техническая ошибка: «Не удалось сформировать отчёт» и «Повторить»; выбранные параметры сохраняются.

### 7.2. Шаг 2 — предварительный просмотр

После успешного формирования показать:

- наименование лаборатории — автоматически, только чтение;
- адрес лаборатории — автоматически, только чтение;
- отчётный период — автоматически, только чтение;
- количество включённых карточек ВСЭ — только чтение;
- семь обязательных кодов для ручного ввода;
- полную рассчитанную таблицу формы — только чтение.

Обязательные коды:

1. код формы по ОКУД;
2. код отчитывающейся организации по ОКПО;
3. код вида деятельности по ОКВЭД;
4. код территории по ОКТМО;
5. код министерства (ведомства), органа управления по ОКОГУ;
6. код организационно-правовой формы по ОКОПФ;
7. код формы собственности по ОКФС.

В MVP проверяется только непустое значение. Не придумывать маски, длины, автоматический поиск по классификаторам и числовое ограничение до подтверждения требований. Пробелы по краям удаляются. Поля всегда пустые при новом формировании и не заполняются из прошлых отчётов.

Кнопка «Изменить параметры» возвращает к шагу 1 и очищает предварительный расчёт и коды. Если хотя бы один код изменён, сначала показать общий диалог о потере несохранённых данных.

### 7.3. Нижняя панель

На шаге предварительного просмотра закреплённая снизу панель:

- «Отмена»;
- «Сохранить отчёт».

«Сохранить отчёт» недоступна, пока не заполнены все семь кодов. После попытки отправки фокус переводится на первую ошибку, поля получают связанные русские сообщения и `aria-invalid`.

Во время сохранения: «Сохраняем…», без повторной отправки. Сетевая ошибка сохраняет предварительный расчёт и введённые коды. Если другой администратор успел сохранить тот же отчёт, показать конфликт: «Отчёт за этот период уже создан» и действие «Открыть отчёт»; не перезаписывать запись.

После успеха перейти на просмотр сохранённого отчёта, а не в список.

### 7.4. Уход без сохранения

Черновика нет. При уходе после формирования или ввода кодов показать общий диалог:

- «Продолжить заполнение»;
- «Выйти без сохранения».

При закрытии вкладки допустим системный `beforeunload`. После подтверждённого ухода предварительные данные не восстанавливаются.

## 8. Официальная таблица формы

### 8.1. Колонки

1. «Наименование показателей»;
2. «№ строки»;
3. «Крупный рогатый скот, яки, буйволы»;
4. «Свиньи»;
5. «Овцы, козы»;
6. «Кролики, нутрии»;
7. «Птица / куры»;
8. «Птица / другие виды»;
9. «Рыба»;
10. «Другие виды животных».

Составной заголовок «Птица» реализовать корректными `colspan`/`scope`, а не визуальной имитацией.

### 8.2. Строки

Сохранить все строки исходного образца и их номера:

- 166–171 — осмотры и виды исследований;
- 172 — специальные лабораторные исследования;
- 173–210 — выявленные болезни;
- 211–216 — мясо, направленное на обезвреживание;
- 221–226 — субпродукты, направленные на обезвреживание;
- 231–235 — мясо, направленное на утилизацию;
- 240–242 — мясо и субпродукты, направленные на уничтожение.

Формулировки строк брать из предоставленной книги. Пропуски в нумерации являются свойством формы и не исправляются.

### 8.3. Представление

- Таблица размещается внутри собственного горизонтально прокручиваемого контейнера; вся страница по горизонтали не прокручивается.
- Закрепить шапку, колонку «Наименование показателей» и колонку «№ строки».
- Пересечение закреплённых областей имеет корректный фон и порядок слоёв.
- Числа выравниваются по правому краю, номера строк — по центру.
- Отсутствующее значение отображается как `0`, а не пустая ячейка и не тире.
- Количества — целые числа.
- Масса — в тоннах с точностью до 0,001 т; исходные килограммы суммируются и только затем делятся на 1000. Формат в русском интерфейсе: `0,000`.
- Рассчитанные ячейки нельзя редактировать и нельзя открывать для детализации в MVP.

На 390 px сохраняются заголовок, коды и действия; широкая форма прокручивается только внутри контейнера. Отдельный мобильный макет не требуется.

## 9. Просмотр сохранённого отчёта

Сверху показать служебную сводку:

- лаборатория;
- отчётное полугодие;
- дата и время формирования;
- количество проведённых ВСЭ.

Служебная сводка не входит в Excel, PDF и печатную форму.

Далее показать неизменяемую шапку организации с семью кодами и официальную таблицу. Никаких полей редактирования и кнопки «Сохранить» нет.

Действия страницы:

- «Скачать Excel»;
- «Скачать PDF»;
- «Распечатать»;
- меню дополнительных действий с «Удалить», если композиция не позволяет безопасно разместить опасное действие рядом с экспортом.

Кнопка «Назад к отчётам» возвращает список с прежними фильтрами и страницей.

Если отчёт не найден или удалён в другой вкладке, не показывать пустую форму: состояние «Отчёт не найден» и переход к списку.

## 10. Печать, PDF и Excel

### 10.1. Печать и PDF

Отдельный макет `admin-report-print.html` содержит только официальную форму:

- без шапки системы, фильтров, служебной сводки и кнопок;
- с наименованием и адресом организации, периодом, семью кодами и полной таблицей;
- с повторением заголовка таблицы на каждой печатной странице;
- без обрезанных колонок и строк на границе страниц;
- с номером страницы, если это допускает выбранный механизм печати.

В исходной книге не задана область и ориентация печати. Для визуального макета использовать альбомную ориентацию и масштабирование по ширине, но конкретный формат бумаги и обязательные колонтитулы вынести на подтверждение перед промышленной генерацией PDF.

«Распечатать» открывает это представление и вызывает системный диалог печати только после готовности разметки. «Скачать PDF» формирует тот же снимок без элементов интерфейса.

### 10.2. Excel

Excel воспроизводит структуру предоставленной книги: шапка организации и официальная матрица, без служебной сводки веб-страницы. Числовые ячейки остаются числами, а не строками. Экспорт строится из сохранённого снимка, а не повторно из текущих карточек ВСЭ.

### 10.3. Имя файла

Шаблон:

`5-вет_раздел-III_<лаборатория>_<год>_<1-или-2-полугодие>.xlsx`

Для PDF используется то же имя с `.pdf`. Кавычки, слеши и запрещённые символы в названии лаборатории заменяются безопасным дефисом; повторные дефисы схлопываются.

## 11. Удаление

Удаление доступно из списка и просмотра через один общий диалог. Показать:

- «Удалить отчёт?»;
- лабораторию;
- отчётное полугодие;
- предупреждение «Отчёт будет удалён без возможности восстановления»;
- «Отмена» и опасную кнопку «Удалить».

Фокус при открытии — на «Отмена». Во время операции: «Удаляем…», закрытие блокируется. Ошибка оставляет диалог открытым и позволяет повторить. После успеха:

- из просмотра перейти к списку;
- из списка удалить строку, пересчитать общее количество и скорректировать страницу;
- удалённое полугодие снова становится доступным для нового отчёта.

Удаление не изменяет карточки ВСЭ и не отменяет ранее скачанные файлы.

## 12. Правила отбора данных

В отчёт входят только сохранённые завершённые карточки ВСЭ мяса выбранной лаборатории, дата завершения которых попадает в полугодие.

- I полугодие: 1 января 00:00:00 — 30 июня 23:59:59;
- II полугодие: 1 июля 00:00:00 — 31 декабря 23:59:59;
- зона времени: `Europe/Moscow`;
- граница определяется датой завершения/сохранения ВСЭ, а не датой поступления, выдачи заключения или отбора проб;
- черновики и незавершённые карточки исключаются;
- молоко и молочная продукция исключаются;
- при сохранении отчёта список исходных идентификаторов входит во внутренний снимок для аудита, хотя в MVP не показывается пользователю.

Поскольку исходные поля карточки ВСЭ должны быть обязательными, отдельный пользовательский сценарий «частично заполненные исходные данные» не проектируется. Техническая ошибка агрегации показывается как ошибка формирования с повтором и диагностическим кодом для поддержки.

## 13. Открытые вопросы к ветеринарам

Эти вопросы **не блокируют создание визуальных HTML-макетов**, где используются явно подписанные демонстрационные значения. Они **блокируют утверждение промышленного алгоритма расчёта**.

1. Что считать в строке 166 «Осмотрено»: одну сохранённую карточку ВСЭ, каждую тушу/полутушу/часть или иной объект учёта?
2. Как именно существующие исследования карточки распределяются между строками 167–172: микроскопические, трихинеллоскопии, физико-химические, радиометрические, другие и специальные лабораторные исследования?
3. Как считать случаи болезней: один случай на карточку, на исследуемую часть или на каждую выбранную болезнь?
4. Как однозначно распределять номенклатуру продукции по официальным колонкам видов животных, включая птицу, рыбу и «Другие виды животных»?
5. Какие исходные данные нужны для отдельных масс мяса и субпродуктов? Текущих сведений об общей массе партии и наличии внутренних органов недостаточно для строк 221–226 и 242.
6. Какие направления и причины ВСЭ соответствуют «обезвреживанию», «утилизации» и «уничтожению» в строках 211–242?
7. Требуются ли дополнительные правила округления и переносов между строками итогов и расшифровок?
8. Какой формат бумаги, колонтитулы и подписи обязательны для официального PDF/печати?

До подтверждения нельзя незаметно превращать демонстрационные правила в бизнес-логику. В mock-адаптере использовать отдельную маркированную фикстуру `demoCalculation`, не смешанную с будущим production-расчётом.

## 14. Демонстрационные данные макетов

- Использовать синтетические лаборатории, не реальные персональные сведения.
- В списке — не менее 25 отчётов за несколько лет и полугодий, чтобы проверить поиск, фильтры и вторую страницу.
- Для сценария создания выбрать лабораторию, у которой доступно I полугодие 2026 и есть карточки ВСЭ мяса.
- Для официальной таблицы заполнить несколько разных колонок и разделов, остальные ячейки показать нулями.
- Демонстрационную матрицу подписать в коде как фикстуру, а не утверждённый результат расчёта.
- Отдельные фикстуры: нет данных, все периоды уже заняты, конфликт сохранения, ошибка формирования, ошибка экспорта, удалённый отчёт.

## 15. Общие компоненты и Storybook при реализации

До верстки провести инвентаризацию. Повторно использовать существующие `AppHeader`, кнопки, информационные поля, диалоги и иконки. Предметные общие элементы разместить в `components/admin/reports/` и использовать один код в страницах и stories.

Кандидаты на выделение:

- `ReportTypeSelect`;
- `ReportFilters`;
- `ReportsTable` и меню действий строки;
- `ReportParameters`;
- `ReportOrganizationHeader`;
- `ReportMatrix`;
- `ReportSummary`;
- `ReportDeleteDialog`;
- адаптер демонстрационного хранилища и генерации.

Это ориентировочная декомпозиция, а не требование создать лишние обёртки. Компонент выделяется, если имеет самостоятельный контракт или повторяется.

Storybook должен показать значимые состояния, а не целые страницы:

- строка списка и меню действий;
- таблица: обычная, загрузка, ошибка, пусто, нет совпадений, длинное название лаборатории;
- параметры: обычное, нет доступных периодов, нет данных, формирование;
- семь кодов: пусто, ошибки, заполнено;
- матрица: широкая, нули, длинные подписи, узкий viewport;
- диалог удаления: обычный, процесс, ошибка;
- административная шапка с пунктами «Управление пользователями» и «Отчёты».

## 16. Доступность и адаптивность

- WCAG 2.2 AA, видимый фокус, русский доступный текст.
- Таблицы имеют `caption`, корректные `scope`, связи составных заголовков и осмысленный порядок чтения.
- Состояния не передаются только цветом.
- Меню и диалоги полностью управляются клавиатурой; после закрытия фокус возвращается инициатору.
- Sticky-панель не перекрывает последние строки и ошибки формы; учесть нижний safe area.
- На 1440, 1024, 768 и 390 px нет горизонтальной прокрутки всей страницы. Горизонтальная прокрутка разрешена только контейнеру официальной матрицы.
- Длинные названия лабораторий доступны полностью через перенос или раскрытие, а не только через `title`.
- Печать не содержит скрытых интерактивных элементов и сохраняет читаемый порядок.

## 17. Критерии приёмки макетов

1. В общей административной шапке справа от «Управление пользователями» появился «Отчёты», без изменения геометрии шапки.
2. Список содержит согласованные колонки, поиск, фильтры, сортировку, пагинацию по 20 записей и строку-ссылку.
3. Все пять действий доступны из одного меню «Действия»; опасное действие отделено визуально.
4. Создание проходит через «Сформировать отчёт» и затем «Сохранить отчёт»; кнопки не подменяют друг друга.
5. Выбрать можно только завершённое свободное полугодие; при отсутствии ВСЭ создание заблокировано с согласованным текстом.
6. На предварительном просмотре семь кодов пустые и обязательные, автоматически рассчитанные сведения не редактируются.
7. После сохранения отчёт полностью неизменяем; повторное сочетание лаборатории и периода невозможно.
8. Сохранённый отчёт открывается из строки, экспортируется из сохранённого снимка и удаляется через подтверждение.
9. Веб-матрица воспроизводит структуру формы, показывает нули и прокручивается внутри собственного контейнера.
10. Печатный макет не содержит интерфейса системы и не обрезает таблицу.
11. Состояния загрузки, пустоты, отсутствия совпадений, нет данных, ошибки, конфликта и удаления показаны и доступны с клавиатуры.
12. Демонстрационные расчёты явно отделены от открытых методических вопросов.

## 18. Проверки при последующей реализации

- После добавления компонентов и stories выполнить `npm.cmd run build-storybook`.
- Проверить реальные HTML-страницы в браузере на 1440, 1024, 768 и 390 px.
- Добавить предметные браузерные сценарии: фильтры и возврат, формирование, обязательные коды, уход с потерей данных, уникальность, сохранение, экспорт, печать и удаление.
- Отдельно проверить клавиатуру, фокус меню/диалогов, внутренний скролл и печатный preview.
- Проверить, что HTML с диска не зависит от `tmp/`, CDN и Storybook-адаптера.
