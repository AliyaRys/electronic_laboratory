# ADR-001: PostgreSQL хранит согласованные рабочие данные

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [Реестр](README.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-COM-05/08, FT-VSE-01/02, FT-SMP-07, FT-RPT-03; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Есть конкурирующие записи врачей, уникальность ВСЭ и необратимое списание. Нужны транзакции, ограничения связей и воспроизводимость отчётов.

## Решение
**Accepted:** PostgreSQL обязателен; DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME задаются раздельно; миграции выполняются отдельно от запуска API.

**Принятое решение:** PostgreSQL 18.6, официальный образ postgres:18.6 с digest из README. Одна БД на установку, лаборатория — область данных, не отдельная база. Рабочие данные нормализованы; JSONB используется для внешнего снимка и зафиксированных вычислений. На старте расширения не добавляются. Индексы по лаборатории, устойчивому ключу, статусу и времени; окончательный набор подтверждается планами запросов. Приложение работает под ролью без DDL, миграции — отдельной ролью. UTF-8; события хранятся timestamptz, правила дня вычисляются в Europe/Moscow.

Именованный volume — рабочий диск, не резервная копия. Приняты ежедневное полное резервирование и непрерывное архивирование WAL вне хоста, шифрование хранилища, ежемесячная проверка восстановления. RPO≤15 минут и RTO≤4 часов — проверяемые цели реализации ADR-023. Размещение — собственный Linux-хост Compose, без управляемой облачной БД.

## Рассмотренные альтернативы
1. SQLite: простое размещение; ограничивает конкурентную запись и не соответствует заданному стеку — отклонено.
2. Отдельная БД на лабораторию: физическая изоляция; усложняет миграции и республиканский доступ — отклонено для MVP.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** Один сервер Compose остаётся единой точкой отказа; резервирование не обеспечивает автоматическое переключение.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
Две параллельные транзакции создания дают одну ВСЭ; восстановление копии сверяет партии, пробы, снимки и интеграционные операции; отсутствие БД не превращается в пустой журнал.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
