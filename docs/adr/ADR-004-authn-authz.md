# ADR-004: Casbin принимает единое решение о доступе

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-003](ADR-003-orm-and-migrations.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-ACC-01–11, FT-ADM-01/02, FT-RPT-01; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Четыре роли ограничены лабораторией, территорией и продукцией; поздняя правка зависит от состояния и даты. Условия включения Casbin из adr_request выполнены.

## Решение
**Accepted:** базовый механизм crudauth; выход за его возможности требует Casbin, без двух источников истины. Область и состояние проверяются на backend при каждом защищённом действии.

**Принятое решение:** crudauth сохраняется как механизм проверки пароля/учётной записи. Авторизация полностью делегируется Casbin: subject, действие, лаборатория/территория, продукция, атрибуты объекта и актуальное время. Deny by default. PostgreSQL — источник назначений, делегирования и политик. Предикат области применяется до поиска/пагинации/счётчиков/экспорта; известный UUID не обходит фильтр. Профиль администратора не даёт чтения рабочих записей. Назначение роли проверяет права делегирования целевой области; изменение собственных полномочий запрещено.

Адаптер — существующий пакет sqlalchemy-adapter 1.9.0 официального PyCasbin; имя sqlalchemy-casbin-adapter ошибочно. Источник API адаптера: https://github.com/pycasbin/sqlalchemy-adapter. Используется sync-адаптер через отдельный sync-пул с драйвером psycopg 3.3.8 и run_in_threadpool; его установка и smoke-проверка входят в платформенные критерии реализации. Enforcer создаётся с актуальным снимком политик на защищённый запрос; межзапросный кеш разрешений отключён. Известный риск per-worker in-memory enforcer исключается отсутствием долгоживущего кеша; переход к TTL/watcher требует нового ADR и сохранения отзыва со следующего запроса. Роли/права из JWT не принимаются как источник истины.

Сеансы сохраняются существующим SessionTransport crudauth с backend="redis"; это механизм, уже используемый форком, без разработки собственного хранилища сеансов в PostgreSQL. Идентификатор сеанса передаётся cookie HttpOnly, Secure, SameSite=Lax; в JavaScript и localStorage он не копируется. CSRF-токен и проверка Origin для изменений. Логин, пароль и API-ключи не попадают в журналы. Выход отзывает текущий сеанс; смена/сброс пароля отзывает все сеансы. Пароль хешируется Argon2id через argon2-cffi 25.1.0 (новая проверяемая зависимость); самостоятельного email-восстановления нет. Параметры доступа: минимум 12 символов пароля, максимум 128, без принудительной периодической смены и без обязательной смеси классов символов; сеанс максимум 8 часов, простой 30 минут; 5 ошибок входа за 15 минут временно ограничивают пару логин/IP на 15 минут. Постоянная блокировка — отдельное действие администратора. Argon2id: memory 64 MiB, iterations 3, parallelism 1; на целевом хосте проверяется задержка хеширования. Первая административная запись создаётся закрытой одноразовой командой при пустом реестре, без стандартного пароля; область и делегируемые роли задаются явно. Повтор команды не создаёт второго bootstrap-admin. После bootstrap создание пользователей идёт только через штатную матрицу делегирования. При недоступности Redis защищённые запросы возвращают 503; потеря сеансов требует повторного входа и не затрагивает рабочие данные.

## Рассмотренные альтернативы
1. Только глобальные crudauth permissions: меньше инфраструктуры; не выражает требуемую область/атрибуты без второго авторизатора — отклонено.
2. Права внутри долгоживущего JWT: меньше чтений БД; блокировка не действует со следующего запроса — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** Чтение политик на запрос и sync-пул увеличивают задержку; нужен нагрузочный замер. Авторизация требует замены разрешающих зависимостей форка, при этом транспорт сеансов сохраняется.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
Матрица 4 ролей × область × действие; подмена UUID; отзыв в соседнем worker; полночь; запрет назначения аналитика без делегирования; logout/back; CSRF.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
