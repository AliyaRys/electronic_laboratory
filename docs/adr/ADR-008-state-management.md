# ADR-008: TanStack Query хранит серверное состояние, Zustand — контекст клиента

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-007](ADR-007-frontend-platform.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-ACC-02/04, FT-COM-01–03/06; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Смена лаборатории и запоздавший ответ не должны показывать данные прежней области. Медицинский ввод нельзя терять из-за refetch.

## Решение
**Accepted:** TanStack Query и Zustand — заданный стек; Redux не добавляется.

**Принятое решение:** TanStack Query 5.106.1 хранит ответы API; ключ включает пользователя, лабораторию, продукцию, параметры списка и идентичность объекта. Zustand 5.0.16 хранит выбранный доступный контекст и несекретные UI-переключатели. URL хранит фильтры/страницу для возврата. Формы хранят ввод локально в памяти. persist для медицинских форм, JWT и рабочих записей отключён; сохраняемых черновиков ВСЭ нет.

При logout/отзыве доступа очищаются Query-кеш, контекст и закрытые формы; смена лаборатории сначала защищает несохранённый ввод, затем отменяет старые запросы и изолирует ключи. После изменения инвалидируются затронутые карточка/очереди/счётчики/пробы, но сохранённый отчёт не пересчитывается. Optimistic update для приёмки, ВСЭ, удаления и списания запрещён: UI ждёт подтверждения сервера. Автоповтор мутаций выключен; повтор использует прежний idempotency key.

## Рассмотренные альтернативы
1. Копировать ответы Query в Zustand: удобно одной подпиской; создаёт два несогласованных источника — отклонено.
2. Хранить формы в localStorage: восстановление после закрытия; противоречит отсутствию постоянных черновиков и увеличивает утечку — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** Закрытие вкладки теряет несохранённый ввод по FT; beforeunload имеет ограничения браузера.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
Поздний ответ лаборатории А не появляется в Б; refresh формы не восстанавливает черновик; сетевой отказ не очищает текущий разрешённый ввод.

Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
