# ADR-009: Radix Primitives дополняются существующими CSS-токенами

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-008](ADR-008-state-management.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-COM-09/10, FT-VSE-03–09; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Radix Primitives даёт поведение, не визуальное оформление. В проекте уже выделены шапка, иконки, компоненты входа и рабочих экранов.

## Решение
**Принятое решение:** Radix Primitives (@radix-ui/react-dialog 1.3.1 как проверенный базовый пакет), без @radix-ui/themes. Визуальный слой — собственный CSS на токенах DESIGN.md и components/app/tokens.css; токены авторизации остаются отдельными. Полный набор Primitives фиксируется по реальным компонентам, добавление пакета требует проверки версии. Не вводятся MUI/Ant Design и Tailwind-конструкторы.

React Router 8.5.1 задаёт маршруты/защиту переходов, react-hook-form 7.91.0 и zod 4.6.7 — локальные формы и клиентскую валидацию. Сервер повторяет все предметные проверки. Storybook сохраняется, @storybook/react-vite 10.6.6 — выбранная версия нового каталога. Новый компонент и его stories используют одну реализацию; существующий JS-компонент не копируется в stories. API VseAuth и реестры AppHeader/VseIcon сохраняются в макетах; адаптация в React выполняется в рамках принятой границы ADR-007, с одним каноническим источником иконок.

Состояния: обычное/disabled/error/loading/длинные данные/узкий экран. Диалог удерживает фокус и возвращает его, Escape закрывает, опасное подтверждение начинает с безопасного действия. Проверка 1440/1024/768/390 px. Формы не заполняют норму/итог автоматически по цвету предупреждения.

## Рассмотренные альтернативы
1. Radix Themes: быстрый визуальный слой; меняет установленную стилистику макетов — отклонено.
2. Собственные модальные окна без Primitives: меньше библиотек; повышает цену доступности и расходится со стеком — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** CSS и доступность требуют сопровождения; новые router/forms — дополнительные зависимости, выбранные этой записью; их типы и обработка ошибок проверяются в первом frontend-этапе.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
В будущем build-storybook и браузерный проход использующего экрана; для входа также test:ui. Проверить клавиатуру и длинные русские названия.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
