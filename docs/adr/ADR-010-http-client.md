# ADR-010: openapi-fetch выполняет запросы единого API

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-009](ADR-009-ui-layer.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-COM-05/07/08; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Клиент обязан соблюдать cookie-сессию, отмену чтений, идемпотентность и формат ошибок.

## Решение
**Accepted:** openapi-fetch и openapi-typescript; Axios не добавляется.

**Принятое решение:** openapi-fetch 0.17.0 с пустым baseUrl (same-origin) и сгенерированными типами. OpenAPI paths содержат полный backend-префикс /api/v1; клиент вызывает путь буквально, например /api/v1/arrivals. OpenAPI servers задаёт /, поэтому префикс не прибавляется повторно. VITE_API_BASE_URL=/api/v1 остаётся относительным пространством API по инварианту; wrapper проверяет этот префикс пути, но не конкатенирует его с уже полным paths. Правило объединения baseUrl/path: [официальная документация](https://openapi-ts.dev/openapi-fetch/). Тонкий общий слой добавляет CSRF, request ID, If-Match, Idempotency-Key и нормализует Problem Details; секреты не пишет в лог. AbortSignal используется для отмены чтений при смене фильтра/области. 401 переводит к входу с очисткой закрытого кеша, 403 показывает запрет, 409 сохраняет доступный ввод и предлагает загрузить актуальное состояние. На экспорт ошибка проверяется до создания файла. Мутации автоматически не повторяются. Poll статуса операции — отдельное чтение с ограниченной задержкой и остановкой на конечном состоянии.

## Рассмотренные альтернативы
1. Axios: знакомые interceptors; дублирует transport и не нужен при заданном клиенте — отклонено.
2. Разрозненный fetch на страницах: минимум обёрток; расходятся ошибки, CSRF и повтор — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** Генерируемые типы не валидируют недоверенный runtime-ответ; backend контракт и контрактные проверки остаются обязательными.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
Проверить отмену старого чтения, 401/logout, 409 с сохранением формы и ошибку PDF без пустого скачанного файла.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
