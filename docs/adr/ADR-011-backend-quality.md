# ADR-011: Backend проходит исполняемые проверки данных и прав

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-010](ADR-010-http-client.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: Все FT v2.0; особенно FT-COM-05/06, FT-ARR-14; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Сборка и проценты покрытия сами по себе не доказывают отсутствие дублей, утечек и ошибок отчётности.

## Решение
**Accepted:** CI блокируют ruff check, ruff format --check, mypy, pytest с порогом покрытия, alembic upgrade head на эфемерной БД.

**Принятое решение:** mypy strict для всего нового backend; глобальные ignore_missing_imports и ignore_errors запрещены. Исключение для конкретной внешней библиотеки требует локального override с причиной/владельцем; SQLAlchemy не исключается. Наследуемые нарушения форка устраняются до первого релиза.

pytest: unit для типизации/норм/Decimal/календаря/5-вет; интеграционные на реальном PostgreSQL для уникальности, rollback, ревизии, удаления, проб и повторов; API-матрица ролей; контракт SOAP/XML; отказ worker/Redis/таймаут. Общий line coverage ≥85%, предметные модули authz/receipt/examination/samples/pricing/reports ≥90%; отсутствие критического сценария не компенсируется процентом. Команды CI: uv run --frozen ruff check backend; uv run --frozen ruff format --check backend; uv run --frozen mypy backend/src; uv run --frozen pytest --cov=backend/src --cov-fail-under=85. Порог 90% проверяет отдельный CI-шаг по coverage.json. Точные пути уточняются только под финальную структуру.

Все SC-001–101 и AT-01–25 из FT получают автоматизированную либо адресно документированную ручную проверку, с учётом O-01–09. Отчёт этой задачи не объявляет их выполненными.

## Рассмотренные альтернативы
1. Только unit и SQLite: быстрый CI; не проверяет PostgreSQL блокировки/constraints — отклонено.
2. 100% строк как единственный gate: простая цифра; допускает пропуск сценария и стимулирует бессмысленные тесты — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** Интеграционная матрица увеличивает время CI и требует поддержки сценарных данных.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
В CI намеренно сломать тип, уникальность и миграцию: соответствующие gates должны упасть; ночные границы проверять управляемыми часами.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
