# ADR-012: Frontend проверяется на уровне компонентов и рабочих сценариев

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-011](ADR-011-backend-quality.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-COM-01–10, FT-ACC-01–04, FT-DOC-05, FT-RPT-08; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Каталог компонентов и успешная сборка не подтверждают связность приложения, права и поведение при ошибках.

## Решение
**Accepted:** ESLint, Prettier, Vitest; CI исполняет eslint, prettier --check, tsc --noEmit, vitest run.

**Принятое решение:** ESLint flat config, TypeScript strict, React Testing Library 16.3.3 и MSW 3.0.4 для доступных имён, формы, конфликта и ошибок API. Playwright 1.65.0 — дополнительная e2e-зависимость этой записи. CI проверяет полный маршрут на Chromium: вход → область → сверка → подтверждение → ВСЭ → документ; отдельно ожидание/поздний итог, удаление/проба, 5-вет и запреты четырёх ролей. Детерминированная модель внешних ответов проверяет UI; не выдаётся за подтверждение ВетИС.

Обязательны npm ci, eslint, prettier --check, tsc --noEmit, vitest run, vite build, сборка Storybook, критические e2e. Обязательный порог line coverage frontend ≥80%, но сценарии важнее процента. Скриншоты/визуальный обзор на 1440/1024/768/390 px с длинными данными. Для текущего каталога сохраняются npm.cmd run build-storybook и для auth npm.cmd run test:ui. Новое приложение получает scripts в следующей задаче, в текущей они не создаются.

## Рассмотренные альтернативы
1. Только snapshot tests: быстро заметить HTML diff; не проверяет права/конфликт/фокус — отклонено.
2. Только ручная проверка: гибкость; не является воспроизводимым CI-gate — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** E2e требует изолированных данных и защиты от нестабильного тайминга.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
Проверить что CI падает на недоступном имени кнопки, неправильном запрете и нарушении маршрута; компоненты проверять и на реальной странице.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
