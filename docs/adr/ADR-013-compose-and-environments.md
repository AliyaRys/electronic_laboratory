# ADR-013: Compose и frontend nginx дают единый origin

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-012](ADR-012-frontend-quality.md); [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-COM-08; adr_request §5; [исходные требования](../../%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F/v2.0/README.md).

## Контекст
Система размещается на собственных стендах; клиентский образ должен переноситься без пересборки.

## Решение
**Accepted:** docker-compose.yml общий для dev/production без version:, bind mounts, reload и опубликованного порта БД. Сервисы backend/frontend/postgres; backend в production только expose. postgres и backend имеют healthchecks, depends_on condition: service_healthy. docker-compose.dev.yml содержит код/reload и 127.0.0.1:${DB_PUBLISHED_PORT:-5432}:5432; запуск dev — docker compose -f docker-compose.yml -f docker-compose.dev.yml. Миграции — отдельный профиль migrate, завершение проверяется до запуска новой версии.

Frontend nginx проксирует location /api/ на http://${BACKEND_HOST}:${BACKEND_PORT} без переписывания URI. Завершающий / в proxy_pass, удаляющий префикс, запрещён. /api/v1 принадлежит backend; Vite proxy совпадает. /openapi.json проксируется отдельным location без SPA fallback. CORS в production не требуется; браузер обращается к одному origin. VITE_API_BASE_URL=/api/v1. BACKEND_HOST/BACKEND_PORT подставляются при старте nginx; envsubst ограничен этими именами, чтобы не затереть $uri. Не-API маршруты имеют SPA fallback.

DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME обязательны; DSN собирается с корректным экранированием, DB_HOST=postgres действует только в compose-сети. Образы приложений маркируются git SHA и закрепляются digest; base images тоже по digest, все процессы non-root, npm ci/uv sync --frozen. latest в production запрещён.

**Принятое решение:** TLS завершается внешним nginx на Linux-хосте установки; frontend nginx слушает непривилегированный HTTP-порт и публикуется только на 127.0.0.1:8080 хоста. Внешний nginx принимает 443 и перенаправляет 80 на HTTPS; сертификат/ключ и FQDN являются значениями установки. TLS 1.2/1.3; backend доверяет forwarded-заголовкам только заданному nginx. Это выбранное размещение прокси, не предположение о существующем корпоративном ingress. Redis и worker добавляются как принятые зависимости ADR-005. Выбраны Docker Engine 29.9.3 и Compose plugin 5.7.0, совместимые с используемыми profiles/healthchecks; Compose-файл не содержит version:. Секреты поступают через закрытый env-file, не входят в Git/образ/логи; права чтения только эксплуатационной учётной записи. ВетИС включается отдельными VETIS_READ_ENABLED и VETIS_WRITE_ENABLED, оба false до разрешённого этапа. API readiness зависит от БД/версии схемы, не от доступности ВетИС; ошибки интеграции видны отдельно.

## Рассмотренные альтернативы
1. Публиковать backend и БД наружу: проще диагностика; нарушает заданные инварианты доступа — отклонено.
2. Встраивать адрес API при сборке: простой deploy; требует разных образов и ломает переносимость — отклонено.

## Последствия
- Решение сохраняет указанные продуктовые ограничения и задаёт проверяемую границу реализации.
- **Риск/цена:** Compose не обеспечивает HA; настройка внешнего TLS, trusted proxy и секретов остаётся эксплуатационной обязанностью.
- Изменение архитектуры оформляется замещающим ADR с причиной и проверкой; изменение продуктового правила согласуется с аналитиком и отражается в ФТ.

## Проверка
Будущие compose config для base и base+dev; убедиться в отсутствии published backend/DB в production, сохранении /api/v1, non-root и переносе одного образа.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
