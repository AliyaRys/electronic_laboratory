# ADR-021: Отчёт сохраняет показанный снимок и воспроизводимые вклады

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-015](ADR-015-module-boundaries.md), [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-RPT-01–09, FT-SMP-05; INPUT-04/05.

## Контекст
Снимок должен переживать исправление/удаление исходной ВСЭ, а повторное формирование использовать текущие данные.

## Решение
Reporting формирует предварительный снимок в короткой REPEATABLE READ транзакции. Отбор по одной лаборатории и first_completed_at в завершённом полугодии Europe/Moscow, полуоткрытые границы. Завершённые местные ВСЭ включены; ожидание/удалённые/прежняя внешняя ВСЭ без местной исключены; ярмарка и внутренняя транзакция включены.

Вклады: 166 +1/ВСЭ; 167 отдельно бактериоскопия+микроскопия; 168 трихинеллоскопия; 169 по pH/пероксидазе/меди; 170 +1 за дозиметрию с двумя значениями; 171 по варке/люминесценции/температуре; 172 +1 при отправке и завершении после ответа. 240 — принятая масса с направлением «На уничтожение» /1000; 241 мясо, 242 субпродукты. Пробы не добавляют уничтоженный вес. Суммирование Decimal до итогового округления; неизвестная/неоднозначная классификация блокирует весь расчёт, не попадает в «Другие» автоматически. Неавтоматические ячейки помечаются нерассчитанными согласно INPUT-04.

Предварительный снимок содержит UUID/ревизии источников и минимальные числовые вклады, версии правил/классификации, матрицу, реквизиты, автора/время. Полного медицинского протокола в нём нет. Сервер возвращает payload с HMAC-подписью, привязанной к пользователю/лаборатории/типу/периоду; клиент держит его в памяти без долговременного черновика. Сохранение проверяет подпись и текущий доступ и записывает именно показанный payload плюс семь вручную введённых текстовых кодов. Пересчёта по текущим ВСЭ при сохранении нет. Изменение параметров уничтожает предварительный снимок/коды после предупреждения. Ключ подписи общий для workers, переживает deploy; старые ключи сохраняются до завершения активных просмотров по политике ADR-023. Payload хранит компактные источники (UUID, ревизия, числовые вклады), не полные результаты. Предельный размер несжатого payload 32 MiB; реализация обязана уложить до 100 000 источников выбранной лаборатории в этот объём. Подпись HMAC-SHA256 включает key_id и session_id; её нельзя перенести в другой сеанс. Сервер отзывает токен вместе с сеансом, ключ ротируется раз в 90 дней, старый ключ проверки сохраняется 9 часов после ротации (8 часов максимума сеанса плюс час запаса). Ошибка сети не уничтожает snapshot в открытой форме; новое формирование после окончания сеанса — явное действие пользователя.

БД обеспечивает максимум один сохранённый тип/лаборатория/год/полугодие. Нет исходных ВСЭ — формирование блокируется. Экспорт/просмотр используют сохранённую матрицу. Удаление отчёта освобождает период, не меняет источники; новый отчёт использует текущие правила. Операционные показатели считают отдельно завершённые факты сверки/услуг, внутреннее исключение применяется только к обработанным партиям. Текущий остаток проб не ограничивается периодом истории.

## Рассмотренные альтернативы
1. Сохранять только параметры и пересчитывать: мало данных; экспорт меняется вслед за удалением ВСЭ — отклонено.
2. Хранить серверный постоянный черновик: проще продолжить; добавляет исключённый долговременный черновик отчёта — отклонено.

## Последствия
- Определена ответственность за данные и проверяемая граница операции.
- **Риск/цена:** Подписанный payload увеличивает ответ и требует предела размера/управления ключами; отсутствие официального образца блокирует официальный экспорт.
- Реализация и ТЗ обязаны сохранить указанные инварианты и обработку отказов.

## Проверка
AT-16–19/22–24; изменить/удалить источник между preview/save, получить прежнюю матрицу; подменить signed payload — отказ; экспорт всех форматов совпадает.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
