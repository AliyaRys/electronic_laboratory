# ADR-022: Единая модель вывода формирует PDF и Excel

- **Статус:** Accepted — архитектурное решение принято автором по прямому поручению владельца продукта 06.11.2026.
- **Дата:** 2026-11-06
- **Ответственность:** агент-разработчик реализует и проверяет решение; аналитик отвечает за изменение продуктовых правил. Дополнительное согласование архитектуры не требуется.
- **Связанные:** [ADR-015](ADR-015-module-boundaries.md), [трассировка](traceability.md).
- **Основание:** ФТ v2.0: FT-DOC-03–06, FT-RPT-08; INPUT-04.

## Контекст
Заключение имеет два основания, отчёт — сохранённый снимок. Печать не подтверждает подпись/вручение/оплату.

## Решение
Documents строит неизменяемую в рамках запроса view-model после проверки доступа/основания. Заключение получает текущее пригодное завершённое основание: местную ВСЭ либо достаточную прежнюю ВСЭ без повторной после подтверждённой приёмки. При повторной клеймо лаборатории, без повторной — убойного пункта. При ожидании/полном возврате/непригодности/неполных реквизитах документ недоступен. Исправление основания меняет следующий вывод; удаление закрывает старый URL, включая кеш.

Выбранные дополнительные библиотеки: WeasyPrint 70.0 для PDF, openpyxl 3.1.5 для XLSX. Версии проверены; проверка совместимости и notices включена в release-gates, не является открытым выбором архитектуры. HTML preview и PDF получают одну серверную view-model; печать использует тот же сформированный PDF, не DOM рабочей страницы. Для отчёта модель берётся исключительно из сохранённого снимка. XLSX содержит числа как числа, семь кодов как текст. PDF — формат бумаги A4, не заявляется соответствие стандарту PDF/A. Официальная геометрия/реквизиты утверждаются INPUT-04.

Шрифты с кириллицей включаются в контролируемые ресурсы; renderer не загружает произвольные URL и не читает пользовательские пути. Текст экранируется, xlsx-строки не превращаются в формулы. Ответы приватные Cache-Control: no-store; экспорт повторно проверяет доступ. Файл формируется целиком до успешного ответа; ошибка не отдаёт пустой успешный файл. Для заключений не вводится отдельный реестр выдачи, электронная подпись и локальный исходящий ВСД.

## Рассмотренные альтернативы
1. Печатать DOM рабочего экрана: мало кода; содержит кнопки и расходится с PDF/Excel — отклонено.
2. Хранить PDF всех старых ВСЭ как доступную историю: быстро скачивать; противоречит удалению без истории — отклонено.

## Последствия
- Определена ответственность за данные и проверяемая граница операции.
- **Риск/цена:** PDF renderer требует системных библиотек и безопасного доступа к ресурсам; официальный образец пока отсутствует.
- Реализация и ТЗ обязаны сохранить указанные инварианты и обработку отказов.

## Проверка
Два основания заключения, длинные русские имена, повтор заголовков, отсутствие обрезки; коды 001 в XLSX; отказ после удаления; равенство матрицы screen/PDF/XLSX/print.

## Открытые вопросы
Незакрытых архитектурных решений нет. Применимые значения настройки и внешние данные перечислены в [контракте входных данных](deployment-and-input-contracts.md); их заполнение не требует повторного выбора архитектуры.
