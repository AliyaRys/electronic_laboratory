# Контракт параметров установки и предметных данных

Версия 1.1, 06.11.2026. Архитектура выбрана в ADR-001–024. Эта таблица описывает значения, которые физически различаются между установками и лабораториями. Они не являются альтернативами архитектуры и не мешают написать полное ТЗ. Агент включает их поставку, настройку, валидацию и отрицательные сценарии в соответствующий этап реализации.

## Правило использования

Неизвестное значение не заменяется демонстрационным. Схема настройки, место хранения и отказ уже определены. Фактическое заполнение секретов/адресов выполняется при установке, предметных каталогов — до работы с зависимым видом продукции. В промышленной БД нет тестовых значений по умолчанию. Наличие схемы настройки не означает, что реальные значения уже получены.

## Параметры размещения

| Значение | Решение и источник фактического значения | Проверка и отказ |
| --- | --- | --- |
| Площадка приложения | Собственный Linux x86_64 хост, Compose; 8 vCPU / 32 GiB / 500 GiB SSD как исходная проектная конфигурация | До запуска проверяются ресурсы, диск, Engine 29.9.3/Compose 5.7.0 и сетевые правила |
| APP_FQDN, сертификат/ключ | FQDN выделяется при установке; TLS внешний nginx, сертификат для этого имени, приватный ключ вне образов/Git | Неизвестный host не обслуживается; сертификат проверяется до открытия HTTPS; self-signed сертификат не выдаётся за доверенный production |
| BACKEND_HOST/PORT | Compose DNS backend и внутренний порт; фронтенд nginx проксирует без URI rewrite | /api/v1 не удаляется/не удваивается; backend/DB не публикуются наружу |
| DB_HOST/PORT/USER/PASSWORD/NAME | Отдельные переменные; DB_HOST=postgres внутри сети; пароль создаётся при установке | Пустой секрет/невалидный порт блокирует startup; DSN не логируется |
| Bootstrap administrator | Одноразовая служебная команда при пустом реестре: логин/ФИО/email/пароль и исходная область/делегирование вводятся при установке | Нет стандартного пароля/публичной регистрации; команда после bootstrap запрещена |
| GitVerse repository, runner, registry URL | Закрытый репозиторий GitVerse; отдельный self-hosted runner; частный Distribution registry ADR-024 | Секреты выдаются только trusted job; runner-image фиксируется digest до исполнения поставки |
| Backup-хост, контакты инцидентов | Отдельный хост/хранилище от app-хоста, исходно 2 TiB, зашифрованный диск; адреса/контакты задаются установкой | Проверяются доставка копии и восстановление; без рабочего backup/ключей production-поставка не проходит release-gate |
| Session/snapshot/служебные ключи | Генерация криптографически стойких секретов при установке; key-ring хранится отдельно от образа | Длина snapshot key ≥256 bit; доступ только служебной учётной записи; все workers используют одинаковый key-ring |

Секретные параметры не раскрываются в ADR, ТЗ, UI и отчётах. ТЗ описывает их назначение/тип/валидацию, а не просит аналитика придумывать реальные секреты.

## Профиль подключения ВетИС — INPUT-01

| Поле/настройка | Принятое правило |
| --- | --- |
| Семейство сервиса | Только ветеринарные управления, mercury-vu.service; нет fallback на сервис ХС |
| Бизнес-операции | Этап 1: GetVetDocumentListOperation. Этап 2: ProcessIncomingConsignmentOperation с полным/частичным принятием/полным возвратом |
| Служебное чтение этапа 2 | GetVetDocumentByUuidOperation, GetStockEntryByUuidOperation и чтение связанных возвратных ВСД; не выполняют исходящую бизнес-операцию |
| Точный endpoint/serviceId с версией, WSDL/XSD/namespace/SOAPAction | Внешние значения зарегистрированного профиля ВУ. Сейчас unverified. Задача адаптера: получить комплект из источника оператора, зафиксировать manifest и checksum всех схем; проверить, что заявленные операции доступны в этом профиле. Ни аналитик, ни агент не конструируют URI по названию wiki-страницы |
| Credentials | Выданные оператором gateway login/password, apiKey, issuerId; хранятся только сервером; сейчас отсутствуют по сообщению пользователя |
| Инициатор | Личный реальный логин внешней системы у пользователя, запускающего обновление/гашение. Автономный общий инициатор для фонового опроса исключён |
| Область | Явная связь лаборатории с ХС/площадкой и классификацией; общая доступность ВУ не расширяет локальный доступ |
| Точность/длины/справочные коды | Ограничения закреплённой XSD и справочников; сервер не округляет молча, не обрезает юридический текст, возвращает адресную ошибку |
| Внешняя идентичность | UUID эВСД; GUID stockEntry и UUID его версии хранятся отдельно; номер документа не ключ |
| До заполнения | Локальные модули разрабатываются через внутренний порт; production-интеграция выключена. Отсутствие подключения не показывает пустой успешный импорт и не подтверждает приёмку |
| Недостаточное доказательство результата | UNKNOWN и INTEGRATION_EVIDENCE_INCOMPLETE; никаких ручных кнопок фиктивного успеха и автоматического повторного submit |

Отсутствие выданного профиля — зависимость задачи подключения последнего этапа, а не необходимость переоткрывать ADR. Если выданный оператором контракт объективно не поддерживает требуемую операцию ВУ, агент фиксирует конкретное несовместимое условие и обращается к аналитику; менять профиль на ХС самостоятельно запрещено. Этот случай нельзя достоверно объявить проверенным до выдачи профиля.

## Предметные каталоги — INPUT-02/03/05

ТЗ обязано задать схему, редактор в пределах полномочий, серверную валидацию и проверку полноты конфигурации. Реальные значения загружаются отдельно от демонстрационных фикстур.

| Набор | Обязательная структура | Поведение без данных |
| --- | --- | --- |
| Методики и нормы | ID продукции/состояния, показатель, методический источник/редакция, тип результата, единица, правило/границы с включённостью; свинина и конина идентифицируются ID | Нельзя ожидание/завершение с отсутствующей обязательной нормой; нельзя выводить «Норма» по фиктивному числу |
| Тарифы исследований | Лаборатория, продукция, показатель, единица принятого количества, цена Decimal≥0 с двумя знаками | Для платной партии обязательная отсутствующая цена блокирует; для ярмарки платная цена не требуется |
| Две услуги сверки | Код услуги, единица, правило множителя, применимость к решению приёмки/возврата, цена, признак фактического выполнения | Применимость и единица — обязательная конфигурация, не скрытый предположенный тариф; без них нельзя завершить платную сверку |
| Сопоставление 5-вет | ID вида Меркурия → одна животная колонка и признак мясо/субпродукты, версия соответствий | Неизвестное/неоднозначное соответствие блокирует весь расчёт; автоматического «Другие» нет |
| Числовая точность | Для внутренних масс хранится NUMERIC(20,6), для денег NUMERIC(20,2); внешние количества хранятся Decimal с исходной точностью в NUMERIC без заданного scale, с отдельным unit ID | Вход с точностью выше 6 для внутренних масс не округляется: ошибка с объяснением; изменение поддержанного масштаба оформляется миграцией. Внешняя точность не теряется |

Конкретные тарифы и ветеринарные нормы не являются архитектурным решением. Архитектура поддерживает согласованную ФТ семантику и запрещает начало зависимой операции без данных. Это позволяет написать ТЗ целиком, не выдумывая стоимость услуг и клинические нормативы.

## Документные ресурсы — INPUT-04

Формы заключения для двух оснований и 5-вет хранятся как версионируемые серверные ресурсы поставки. В manifest формы входят form_id, версия, дата, checksum шаблона, обязательные реквизиты, бумага A4, поля/повторяемые заголовки, правила нерассчитываемых ячеек и число знаков тонн. Семь отчётных кодов — текстовые поля пользователя, не часть справочника.

До получения официального образца агент реализует renderer, единый view-model и визуальные проверки с существующим макетом как рабочим образцом. У такого шаблона признак official=false; вывод помечается «Предварительная форма» и не объявляется официально эквивалентным. Замена ресурса официальным образцом не меняет бизнес-расчёт и API документа. Включение official=true требует фактического эталона и сравнения реквизитов/геометрии; это проверка ресурса, а не новое согласование архитектуры.

Точность тонн до загрузки официального manifest: 6 знаков при отображении, без промежуточного округления; в PDF/XLSX одинаково. Manifest может задать официальную точность отображения; версия/точность сохраняются в снимке отчёта. Неавтоматические ячейки предварительной формы обозначаются «Не рассчитывается», не заполняются ложным нулём.


## Усиленная долговечность удаления ВСЭ

Обычные записи имеют RPO≤15 минут; подтверждённый DELETE ВСЭ — RPO=0 при потере одного app-хоста благодаря remote-flush WAL на backup-хост. При отсутствии backup нельзя подтвердить удаление (503 до отправки COMMIT, UNKNOWN при потере ответа во время COMMIT); данные не восстанавливаются из старой формы и команда не повторяется вслепую. RTO≤4 часа относится к потере app-хоста с исправными backup/ключами. Это принятая техническая цена запрета появления удалённой карточки после аварии; дополнительных продуктовых действий восстановления нет.
