# ADR-NNN: Решение в утвердительной форме

- **Статус:** Proposed
- **Дата:** YYYY-MM-DD
- **Владелец:** автор решения / агент реализации
- **Связанные:** ссылки на существующие ADR
- **Основание:** версия ФТ, точные FT-ID, входы INPUT/OPS

## Контекст
Какое ограничение требует решения. Что уже Accepted заказчиком.

## Решение
Один проверяемый выбор. Указать границу действия, источник версии, ответственность и поведение при отказе. Допущения отделить от утверждённых требований.

## Рассмотренные альтернативы
1. Первая альтернатива: плюс, минус, причина отказа.
2. Вторая альтернатива: плюс, минус, причина отказа.

## Последствия
- Польза.
- Риск и цена решения.
- Обязательства команды.

## Проверка
Наблюдаемые условия, подтверждающие решение; это план будущей проверки, а не отчёт о выполнении.

## Открытые вопросы
Незакрытый продуктовый вопрос адресовать аналитику с объяснением влияния. Технический выбор выполнить самостоятельно в рамках поручения; физические значения установки описать отдельным контрактом параметров.

После принятия зафиксировать дату и согласующих. При замене создать новый ADR, здесь поставить Superseded by ADR-NNN. Историческую запись не удалять.
