Дата: 2026-11-10. Ветка: `feature/DR2-reconciliation-ui`.
Спецификация: `dorabotka/2026-11-10-reconciliation-page-match-evsd-check-usmanov.md` (§1–19).
Эталон: `evsd-check-usmanov.html` (в репозиторий не входит).

## Что сделано

- Полностью переоформлен React-экран `/labs/:labId/arrivals/:partyId/reconciliation`
  (`ReconciliationPage.tsx`, `ReconciliationForm.tsx` + новые компоненты):
  рабочая область 1180px, строка заголовка с бейджем «Меркурий» и хлебными крошками,
  8 секций в каноническом порядке (Документ, Участники перевозки,
  Ветеринарно-санитарная оценка и идентификация транспорта, Идентификация продукции,
  Сопроводительные документы, Ранее проведённая ВСЭ, Результаты сверки,
  Расчёт стоимости услуг) с иконками из общего реестра (`data-check-section`).
- Новые общие компоненты: `CheckSectionCard.tsx`, `ReconciliationActions.tsx`
  (липкая нижняя панель), `ReconciliationFeedback.tsx` (проблема → StatusView).
- Стили вынесены в `reconciliation.css`; из `arrivals.css` удалены старые правила
  сверки (сохранены `.vse-check-note` и правила списка). В `shared/ui/ui.css`
  добавлены семантические алиасы токенов (`--app-match-*`, `--app-mismatch-*` и др.).
- Отметки сравнения — нативные radio (40×40 иконные кнопки со скрытым input),
  aria-имена «Совпадает: <поле>» / «Не совпадает: <поле>», фокус-кольцо 3px #75bfc2,
  цвет не является единственным сигналом.
- «Все соответствует» отмечает только реально сравненные поля; «Погасить» — не
  обычное сохранение: этап гашения всегда preview → явное подтверждение (W03),
  диалог `ReceiptConfirmationDialog` с фиксированной шапкой/фокусом/Escape/focus-trap,
  последствий по каждому решению. Никаких alert/confirm/prompt.
- Переименования для пользователя: «Ранее проведённая ВСЭ», «Результаты сверки»,
  «Расчёт стоимости услуг»; служебные идентификаторы FT-ARR-05/CHK-F41 скрыты.
- Отсутствующие на сервере данные показываются честно («—», пустое состояние
  стоимости: «Стоимость будет рассчитана после сохранения и подтверждения сверки»).
- Десятичные значения — строки, без JS-float; введённые данные сохраняются при
  сетевой ошибке; If-Match/idempotency/conflict — без изменений (`computeAllowedDecisions`,
  формирование акта, full/partial/return — сохранены).

## Отклонения от макета (честно)

1. Бейдж «Меркурий» — CSS-пилюля с точкой, без растрового логотипа
   (в React-приложении нет такого ассета; в макете — изображение).
2. Таблица «Расчёт стоимости услуг» не содержит цен: на сервере `ServiceItem`
   несёт только `{code, performed}` — тарифов/сумм нет, показано честное
   пустое состояние вместо выдуманных цифр.
3. Верхняя оболочка (AppHeader React) отличается по оформлению от тулбара
   статического макета; контентная часть соответствует.
4. Sticky-панель действий в макете имеет более светлый фон; в реализации —
   белый с blur (контраст и состав кнопок сохранены).

## Замечания по окружению e2e (не относится к коду DR2)

  добавлен мок `receipt-context` (ранее при живом бэкенде отвечал 401 и
  ронял сессию).
- `playwright.config.ts`: локально ограничено 2 воркерами — под 6 параллельными
  воркерами casbin-пул бэкенда отвечает 503 (честный флак).
