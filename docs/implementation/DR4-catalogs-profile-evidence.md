- `/catalogs`, `/profile` → HTTP 200;

PNG в контейнере проверено (см. выше).

## API-gaps (сервер не поддерживает — не имитируем)

1. `ScopeView` несёт только идентификаторы (`laboratory_id`,
   `product_scope_id`, `territory_id`) без человекочитаемых названий.
   Блок «Доступные типы продукции» из макета не рисуется; вместо него в правой
   карточке — честное информационное поле «Области доступа» с количествами
   («Лаборатории: N · Виды продукции: N …»), без сырых UUID.
2. В API нет названия учреждения/города для текущего пользователя — поле
   «Учреждение» макета не рисуется.
3. В API нет даты регистрации — поле макета не рисуется.
4. У разделов справочников нет delete-контракта в обзоре — кнопки «Удалить»
   не переносятся из демонстрационного HTML.

## Остающиеся отклонения от макетов

- Иконка секции «Список справочников»: в реестре нет иконки «список» из
  макета, использована семантическая `directories-classic`; иконки карточек —
  `directory-paid-services` из реестра и текстовые знаки «₽»/«≋» из макета.
- Поля профиля/области — только подтверждённые API данные (см. API-gaps).
- Высота карточек профиля `min-height: 560px` соответствует макету, но при
  реальных длинных данных карточки растут по контенту.
