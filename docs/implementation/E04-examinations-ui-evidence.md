# E04 — Карточка ВСЭ, журнал и поздний итог (evidence)

Задача: подключить экраны жизненного цикла ВСЭ к API-05/06 (создание, журнал,
карточка, поздний итог, удаление). Ветка `feature/E04-ui`.

## Что сделано

- Слой API `frontend/src/features/examinations/api.ts` на едином транспорте
  F01 (openapi-fetch): `createExamination` (POST
  `/api/v1/examinations/parties/{party_id}`, If-Match ревизии партии),
  `updateExamination` (PUT `/api/v1/examinations/{examination_id}`),
  `completeWaiting` (POST `/api/v1/examinations/{examination_id}/complete-waiting`,
  строго `OutcomeWrite`), `deleteExamination`, `fetchExamination`.
- Форма только в памяти (`ExaminationForm.tsx` + RHF): никакого черновика,
  автосохранения и кнопки «Сохранить как черновик» нет ни в одном состоянии
  (AT-25). После успешного сохранения форма снимает флаг «грязного» ввода,
  чтобы программная навигация на карточку не блокировалась диалогом покидания.
- Строго отдельные действия: «Отправить в ожидание результата» (POST WAITING),
  «Завершить ВСЭ» (POST COMPLETED), «Сохранить правку» (PUT, только тот же
  день), «Завершить ожидание» (complete-waiting, только итог/направление),
  «Удалить» (DELETE через диалог). Комбинированных кнопок нет.
- Проба: REUSE — значение по умолчанию при наличии доступной пробы той же
  партии; NEW — вес 0,8 кг и текущая дата по умолчанию; EDIT — правка
  связанной пробы с ожидаемой ревизией.
- Итог-матрица зеркалирует сервер: FIT→SALE без причины; UNFIT→
  утилизация/уничтожение с обязательной причиной; «Условно-пригодно»
  отсутствует; ничего не подставляется автоматически.
- Ошибки: читаемые клиентские проверки на подаче; 409
  REVISION_CONFLICT/STATE_CONFLICT сохраняет введённые значения и показывает
  актуальное состояние (без «тихого» повторного подтверждения).
- Журнал `/labs/:labId/examinations` — проекция `GET /api/v1/arrivals`
  (result=WAITING|COMPLETED), отфильтрованная до карточек
  (`examination_id !== null`); WAITING и COMPLETED различаются текстом и
  цветом; строки ведут на реальные карточки.
- Карточка `/labs/:labId/examinations/:examinationId`: шапка — текущая сессия,
  specialist = `view.created_by`; участники перевозки, четыре уровня
  классификации и принятый объём — только чтение; WAITING не показывает
  заключение (SC-047) и не предлагает печать/скачивание; после дня создания
  доступны только действия над итогом (AT-07).
- Storybook: `examination.stories.tsx` (форма, итог, партия, строки журнала,
  диалог удаления, узкие экраны); страницы и stories используют один и тот же
  код компонентов.
- E2E `frontend/tests/e2e/examinations.spec.ts` — 10 тестов (см. ниже).

## Честные ограничения

- Маршрут DELETE `/api/v1/examinations/{examination_id}` отсутствует в
  объединённом контракте этой задачи, поэтому вызов типизирован `as never`
  против сгенерированного клиента (`api.ts`, документировано в коде). Поведение
  диалога при 409/204 покрыто тестами и соответствует контракту E03.
- E2E-ноги, требующие реального API (`identity.spec.ts`, `catalogs.spec.ts`,
  часть `arrivals.spec.ts` — 8 тестов), в этой среде падают на
  `ECONNREFUSED 127.0.0.1:8000` и падали до изменений тоже (проверено
  `git stash -u`). Спецификация `examinations.spec.ts` следует честному
  MSW-паттерну задач S02/S03: маршруты перехватываются `page.route`, запросы и
  полезные нагрузки проверяются реально (body POST, DELETE-счётчик), но это
  моки, а не живой бэкенд.
- «Подтверждение приёмки» в фикстурах e2e — тестовый объект, не данные
  предметной области приложения; номера и UUID фиксированные.
- Индикаторные UUID захардкожены из серверного неймспейса
  (`elab-vse://field/VSE-Fxx`, uuid5); источник и вывод задокументированы в
  `indicators.ts`.

## E2E-покрытие (`examinations.spec.ts`)

1. REUSE по умолчанию; шапка=текущая сессия; партия/объём только чтение; нет
   черновика, исходящего документа, частей/головы/органов, «условно-пригодно»;
   POST WAITING с `sample: REUSE`, без итога.
2. NEW без доступной пробы: 0,8 кг и сегодняшняя дата, REUSE недоступен.
3. COMPLETED: payload `mode/outcome/direction/reason` по матрице; направление
   заблокировано до выбора итога; карточка показывает сохранённый результат.
4. Подача без обязательных исследований: ошибка на экране, ноль сетевых
   запросов.
5. 409: значения не очищаются и не объединяются, показано актуальное
   состояние.
6. WAITING-карточка без заключения; старая карточка без правки/удаления;
   поздний итог — отдельный POST с телом только `{outcome, direction}`.
7. Диалог удаления: необратимость и сохранность внешних документов/проб/отчётов,
   фокус на «Отмена», 409 → «прежнее подтверждение не применено», затем 204 →
   переход в журнал.
8. Грязная форма: диалог «Несохранённый ввод», «Остаться» сохраняет ввод,
   «Покинуть без сохранения» уходит без скрытого сохранения.
9. Журнал: только реальные карточки, вкладки статусов, переходы по строкам.
10. Узкий экран 390: блоки формы идут стопкой (исследования → проба → итог).
