# Локальный справочник продукции Меркурия второго уровня

Дата решения: 07.11.2026.

## Основание

Владелец продукта предоставил pilot-ответ `GetProductByTypeList` для `productType=1` с 28 записями и уточнил правило обязательности трихинеллоскопии. В ответе входящих эВСД `batch.product` передаёт идентификаторы второго уровня, но не его текстовое название. `batch.productItem.name` относится к четвёртому уровню и не может использоваться как название второго уровня.

Исторический `product_foundation` не изменён. Актуальное уточнение оформлено как решение владельца O-10 в функциональных требованиях v2.0.

## Реализация

- Миграция `0005_mercury_product_lvl2` создаёт `mercury_product_guid_lvl_2` и загружает все 28 записей pilot-ответа.
- Стабильный ключ — `(contour, guid)`; текущая версия хранится отдельно в `current_uuid`.
- API и будущий экран поступлений получают русское название из локального справочника, без ProductService-запроса при каждом чтении.
- Неизвестный идентификатор останавливает разрешение с `MERCURY_PRODUCT_DICTIONARY_MISS`; сырой GUID не используется как пользовательское название.
- Pilot и production не смешиваются.

## Трихинеллоскопия

`requires_trichinelloscopy=true` установлен ровно у четырёх GUID:

| Продукция | GUID |
| --- | --- |
| свинина | `57a674fd-ca2b-c523-6853-72d27b4ae32c` |
| конина | `64930556-cbb2-13db-bcdc-572eb188e45e` |
| субпродукты и жиры свиные | `40dd45d4-75aa-b984-4fdb-291f84afad03` |
| субпродукты и жиры конские | `16d9f824-a5f3-6837-3073-e54c4ed5d74d` |

Правило применяется по идентификатору и локальному флагу, не по совпадению текста названия.

## Граница следующих задач

A01 должен сохранить `product`, `subProduct` и `productItem` раздельно и присоединить справочник второго уровня к `IncomingView`. V01 нормализует эти уровни без подмены. V02 позже может атомарно обновлять зеркало ProductService полным проходом; ошибка обновления не удаляет последний успешный снимок.
