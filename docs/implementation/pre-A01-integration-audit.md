# Интеграционная проверка перед A01

Дата: 07.11.2026

Проверена линейная цепочка задач от I01 до C02 перед присоединением к `main`.

## Исправленные дефекты

1. PostgreSQL 18.6: volume в `docker-compose.yml` перенесён с устаревшего
   `/var/lib/postgresql/data` на `/var/lib/postgresql`. До исправления контейнер
   завершался с официальной диагностикой PostgreSQL 18; после исправления
   изолированный Compose-проект достиг состояния `healthy`.
2. Session CSRF после F5: cookie `vse_csrf` теперь имеет `Path=/`, поэтому SPA
   восстанавливает login-issued token из cookie после потери памяти. Session
   cookie по-прежнему HttpOnly. Добавлены backend/unit/e2e-регрессии; e2e
   выполняет `page.reload()` непосредственно перед защищённой мутацией.
3. Источники: точные `AGENTS.md`, `ФТ-v2.0.zip` и каталог
   `Функциональные требования/v2.0` восстановлены из доступных исходников;
   проверенные SHA-256 совпали с `sources-manifest.json`.
4. Pricing mandatory set приведён к ФТ v2.0: VSE-F18, VSE-F19 и VSE-F20
   универсальны, VSE-F21 — один условный показатель для свинины/конины. Удалена
   ложная модель из двух глобально обязательных псевдопоказателей pig/horse.

## Уточнённые сообщения

- Ruff 0.15.12 не повреждён. Для `target-version = "py315"` он применяет
  разрешённый PEP 758 синтаксис `except A, B:`. Результат компилируется Python
  3.15 и проходит Ruff, mypy и pytest.
- Точная версия `DESIGN.md`, указанная в manifest, всё ещё отсутствует. Найденная
  старая копия имеет другой hash и намеренно не подменяла источник. Runtime это
  не ломает, но будущие визуальные изменения нельзя принимать без восстановления
  эталонного файла.
- Для E01 всё ещё потребуются exact product-species IDs свинины и конины, чтобы
  условно применять единый VSE-F21. Это вход задачи E01, а не основание глобально
  требовать трихинеллоскопию от любой партии.

## Git до интеграции

`main` находился на baseline `4029c68`; ветки задач не были присоединены к нему.
Ветки образуют линейную последовательность:

`I01 -> I02 -> I03 -> F01 -> F02 -> F03 -> C01 -> C02`.

Поэтому их безопасно присоединять к `main` строго в этом порядке с
fast-forward, затем присоединить эту интеграционную поправку.
