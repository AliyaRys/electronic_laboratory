# Capacity: цели нагрузки и воспроизводимый прогон (O03, OPS-03)

## Контрактный профиль (Global Constraints ТЗ 09)

| Параметр | Значение |
| --- | --- |
| Длительность | 30 минут |
| Смесь запросов | 80% чтения / 20% записи |
| Одновременные пользователи | 100 |
| Лаборатории / сотрудники | 100 / 500 |
| Новые поступления | 5 000 в сутки |
| Источники отчёта | 100 000 на лабораторию за полугодие |
| Хост | 8 vCPU / 32 GiB / 500 GiB SSD |
| p95 чтения страниц | ≤ 2 с |
| p95 локального сохранения | ≤ 3 с |
| Доля ошибок | < 1% |
| Расчёт 5-вет | ≤ 60 с |
| Несжатый payload 100k источников | ≤ 32 MiB (OPS03) |

Профиль и пороги закреплены в `tests/load/local-scenarios.py::FULL_PROFILE` и
проверяются тестом `test_load_profile_matches_global_constraints`.

## Воспроизводимая команда

Сценарий всегда выполняется **только против изолированных disposable-ресурсов**
(отдельные контейнеры PostgreSQL 18.6 и Redis с одноразовыми томами, никогда не
против стендов организации или dev-стека с данными). Ошибки изолированности
(production env) запрещены в самом сценарии.

### Короткий реальный прогон (масштабированная производная, минуты)

Подготовка одноразовых контейнеров:

```sh
docker run -d --rm --name vse-load-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=vse -p 127.0.0.1:5499:5432 postgres:18.6@sha256:bd5dfa494a5a259704365813dbfa5fa6b3e69be7348d43b547f540c730478583
docker run -d --rm --name vse-load-redis -p 127.0.0.1:6399:6379 redis:8.10.3-alpine3.23@sha256:71885d8cc6e42f2bc0aa2eb853bfc4be200b5108a46ac50e117ae1df0531fb80
```

Прогон (миграции, засев fixtures, подъём uvicorn, логин, смесь, контроль):

```sh
uv run python tests/load/local-scenarios.py --short \
  --database-url postgresql+asyncpg://postgres:postgres@127.0.0.1:5499/vse \
  --redis-url redis://127.0.0.1:6399/0
```

Сценарий проверяет корректность (объём списка = засеянному, ETag растёт при
сохранении) и **утечку объёма** (чужая лаборатория/партия → 403, отключённый
ВетИС → 503 `INTEGRATION_NOT_CONFIGURED`), затем измеряет p50/p95/max по
операциям и долю ошибок; бюджет payload 100k ≤ 32 MiB измеряется в каждом
прогоне. После прогона одноразовые контейнеры останавливаются (изначально
запущены с `--rm`).

### Полный контрактный профиль

Полный 30-минутный прогон со 100 одновременными пользователями выполняется той
же программой в режиме контурного стенда (uvicorn на выделенном хосте
8 vCPU/32 GiB/500 GiB SSD) **оператором**, после фактической подготовки
100 лабораторий / 500 пользователей / 5 000 поступлений в сутки. Эта задача его
**не выполняла** и его не заменяет; результат полного профиля должен быть
зафиксирован отдельной evidence-записью с командой, датой и числами. Пока его
нет — полная производственная готовность по нагрузке не заявляется.

## Фиксация честности

- Fixture-данные сценария никогда не объявляются реальной ВетИС-выгрузкой.
- Короткий прогон объявляет только свои измеренные числа (см.
  `O03-observability-evidence.md`), не распространяя их на полный профиль.
