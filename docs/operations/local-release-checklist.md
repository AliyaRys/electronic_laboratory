# Local release checklist: выпуск локального контура (O03)

Формат статуса по SPEC-06: только `passed` / `failed` / `not-run (причина)`.
Локальные заглушки и fixture-данные не подтверждают ВетИС и не заменяют
официальную приёмку.

| `docker compose config --quiet` (при изменении compose) | passed (O01) |

## 4. Внешние входные данные — обязательное условие официальной готовности

Официальная готовность (юридически значимая приёмка) устанавливается **только**
с реально предоставленными оператором данными:

| Вход | Содержание | Статус |
| --- | --- | --- |
| INPUT-02 | Реальные методики/нормы ответственного ветметодиста | not-run — нужны реальные данные владельца |
| INPUT-03 | Реальный прейскурант + правила двух CHECK-услуг | not-run — нужны реальные данные владельца |
| INPUT-04 | Официальные эталоны форм (5-вет, заключение) | not-run — официальный=false, «Предварительная форма» |
| INPUT-05 | Реальная карта классификации + lvl2 справочник владельца | not-run — pilot seed ≠ юридический источник |
| Backup host | Реальные адрес/host key/replication secret/диски | not-run — см. раздел 2 |

Fixture-данные (pilot seed 07.11.2026, тестовые нормы/цены) являются
контрактными fixtures и **не объявляются** real ВетИС и не считаются
официальными значениями владельца.

## 5. Границы выпуска локальных модулей

- ВетИС read/write для локального выпуска: `write/read=false` (write запрещён
  всегда до отдельного решения владельца; read включается только после V01).
- `VETIS_WRITE_ENABLED=false` во всех средах; write credentials не существуют.
- Отключённый adapter отвечает 503 `INTEGRATION_NOT_CONFIGURED` честно.

## 6. Не выполненные внешние проверки

Запланированные SC/AT с участием внешних систем остаются **not-run до V01/V02**:
production read-профиль ВУ, реальные ВУ credentials/manifest, живой GetVetDocument
и gашение не выполнялись и не проверялись в этой задаче. Не выполненные проверки
не объявляются пройденными.

## 7. Сигнатура готовности

Локальный выпуск разрешается при одновременном выполнении: разделы 1–2 passed,
раздел 3 без failed, раздел 4 — либо passed (реальные данные), либо явно
включённые временные ограничения с датой и ответственным. Любое «passed» без
реальных INPUT-02–05/backup — фальсификация readiness и запрещено.
