# Maintenance: сопровождение и обновления (O03)

## Регламент

- **Раз в месяц** — плановая проверка upstream-обновлений: PostgreSQL 18.6,
  Redis 8.10.3, nginx 1.30.6, Distribution 3.1.2, Docker Engine/Compose,
  Python/Node базовых образов; для каждого — версия, changes, влияние.
  Обновление выполняется только через отдельный upgrade-коммит с диагностикой
  и полным CI (`SPEC-03`, `upgrade.md`); lock не обновляется молча.
- **Обновления безопасности** — по выходу; компонент с критической уязвимостью
  получает оценку влияния **не позднее 1 рабочего дня** и, при подтверждённом
  риске, внеочередной upgrade-коммит. Оценка записывается даже при выводе «не
  затрагивает».
- **Без auto merge**: никакие автоматические слияния/деплои произвольных
  main-коммитов не разрешены; production job запускается только явным
  поручением владельца (`O01`, release.yml). Недоверенный PR не получает
  registry/deploy secrets.
- **Секреты**: ротация ключей подписи preview — 90 дней со старыми ключами в
  режиме проверки ещё 9 часов (`core/keyring.py`); сеансы — max 8 ч, idle 30 мин.

## Ежемесячный restore drill

Ежемесячный drill из `restore.md` обязателен; без свежего evidence readiness
остаётся false и DELETE честно отвечает 503.

## Проверки после обновлений

1. `docker compose config --quiet`.
2. Полный backend gate (`SPEC-06`): ruff/mypy/pytest `--cov=backend/src
   --cov-fail-under=85`.
3. Install smoke без ВетИС (`install.md`).
4. Короткий нагрузочный прогон `tests/load/local-scenarios.py --short`
   (`capacity.md`) — контроль деградации латентностей.
5. Fresh evidence (`docs/operations/*-evidence-*.md`) до следующего релиза.

## Журнал

Каждая оценка/обновление фиксируется датой, компонентом, версией до/после и
решением. Записи не удаляются (срок — 365 дней, см. `retention.md`).
