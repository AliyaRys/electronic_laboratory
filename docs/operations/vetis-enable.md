# Управляемое включение гашения ВетИС

Гашение — юридически значимая внешняя операция. Без отдельного решения
владельца установки значение `VETIS_WRITE_ENABLED` остаётся `false`.
Автотесты, smoke-проверки и действия ИИ-агентов не являются основанием менять
этот флаг или отправлять `ProcessIncomingConsignment`.

## До включения

Оператор вместе с владельцем системы должен подтвердить:

1. Закреплённый manifest ВУ и его WSDL/XSD checksum не имеют `PENDING`.
2. Серверные credentials, issuer, business member, площадка и личные
   инициаторы пользователей заданы через закрытый env-file и не находятся в
   Git, образах, логах или браузере.
3. Read-синхронизация нужной площадки прошла полностью; получатель и контур
   совпадают с зарегистрированной привязкой лаборатории.
4. Нет незавершённых операций `SUBMITTING`, `PROCESSING` или `UNKNOWN`, которые
   требуют сверки по журналу и инструкции `unknown-operations.md`.
5. Владелец письменно назначил окно включения и ответственного оператора.

## Включение

1. Остановить worker, оставив веб-приложение доступным для чтения.
2. В закрытом env-file установки изменить только
   `VETIS_WRITE_ENABLED=true`. Не добавлять значение в compose-файл или Git.
3. Перезапустить backend и worker штатной процедурой развёртывания.
4. Проверить readiness, журналы redaction и страницу сверки: уполномоченный
   ветврач должен видеть «Подготовить гашение», но оператор не нажимает кнопку
   и не создаёт пробное гашение.
5. Зафиксировать в журнале релиза время, владельца решения и digest образов.

Само гашение выполняет только уполномоченный пользователь для конкретного
реального эВСД. Он проверяет preview и отдельно нажимает «Погасить эВСД».
HTTP 202 означает только принятие операции в работу. Локальная ВСЭ становится
доступна лишь после состояния `CONFIRMED` с полным доказательством состава.

## Неопределённый результат и откат

- При `UNKNOWN` запрещены повторная отправка, force-success и ручная подмена
  подтверждения. Допустимо только «Проверить результат» и разбор по
  `unknown-operations.md`.
- Для немедленного запрета новых отправок вернуть
  `VETIS_WRITE_ENABLED=false` и перезапустить backend/worker. Уже отправленные
  операции не удалять: polling/reconcile должны сохранить их доказательства.
- Выключение флага не является отменой уже принятого Меркурием запроса.

## Приёмка без внешней записи

Рабочее enabled-состояние проверяется только офлайн через внедрённый spy:
preview → явное подтверждение → ровно один submit → polling →
`CONFIRMED`/`REJECTED`/`UNKNOWN`. Живой вызов
`ProcessIncomingConsignment` остаётся `not-run by O-13` до отдельной команды
владельца на конкретный документ.
