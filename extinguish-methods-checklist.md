# Чек-лист: метод API Меркурия при несоответствии полей сверки

**Назначение:** определяет, какую операцию `ProcessIncomingConsignment v2` использовать при завершении сверки данных (`evsd-check-usmanov` и родственные макеты), когда ветврач выбрал решение о судьбе партии, но часть полей отмечена «Не соответствует». Решение о методе остаётся за ветврачом; система только блокирует технически неисполнимые сочетания и предлагает допустимую альтернативу.

**Источники:** ProcessIncomingConsignment v2 (справочная система Россельхознадзора, версии 6.7 — разделы «Сценарий 1.1.x / 1.2.x»); каталог полей сверки v1.5 (08-field-catalog.md, CHK-F01–F30, D-72–74); макет `evsd-check-usmanov.html`.

---

## 1. Три метода API и когда они применимы

| Метод | deliveryFacts/decision | Что передаётся | Ограничение по несоответствиям |
|---|---|---|---|
| **Полное гашение** | `ACCEPT_ALL` | `delivery/consignment` (фактические сведения), `discrepancyReport` при расхождении | Допустимо расхождение **только** полей из «белого списка» (раздел 2). Иное несоответствие → ошибка API, полное гашение невозможно |
| **Частичное гашение** | `PARTIALLY` | `delivery/consignment` (принимаемый объём), `returnedDelivery` (возвратная часть), `discrepancyReport` при расхождении | Тот же «белый список». Объём принятой + возвращаемой части должен равняться объёму ВСД в пределах допуска 5% (иначе API требует акт о несоответствии) |
| **Полный возврат** | `RETURN_ALL` | `returnedDelivery` на весь объём ВСД; `consignment` и `discrepancyReport` не передаются | Списка ограничений нет: полный возврат возможен **при любом** несоответствии |

Допуск объёма: система Меркурия «молча» принимает расхождение объёма до ±5%; при больших расхождениях для полного/частичного гашения требуется акт (`discrepancyReport`). Бизнес-порог нашего продукта — ±10% с предложением возврата сверх порога (D-72/73) — он уже API-допуска и не конфликтует с ним.

## 2. Соответствие полей макета полям API

| Поле макета (CHK-ID) | Поле API | Несоответствие допустимо при полном гашении |
|---|---|---|
| ТТН — номер, дата (CHK-F22) | `waybill/issueNumber`, `waybill/issueDate` | Да |
| Номер ТС (CHK-F17) | `transportInfo/transportNumber` | Да |
| Номер прицепа (CHK-F18) | `transportNumber` (прицеп) | Да |
| Вес (CHK-F13) | `consignment/volume` | Да, в пределах 5% — без акта; свыше — с актом |
| Количество (CHK-F12), маркировка частей | `consignment/volume`, маркировка/productItem | Да |
| Срок годности (CHK-F15) | `consignment/expiryDate` | Да |
| Наименование/вид продукции — товарная позиция (CHK-F09/10) | `productItem` (4-й уровень справочника) | Да; уровни 1–3 (`productType`, `product`, `subProduct`) — **нет** |
| Отправитель, адрес (CHK-F05/06) | `delivery/consignor` | **Нет** |
| Получатель, адрес (CHK-F07/08) | `delivery/consignee` | **Нет** |
| Производитель (CHK-F11) | `consignment/origin/producer` | **Нет** |
| Дата выработки (CHK-F14) | `consignment/dateOfProduction` | **Нет** (исключение 6.7: текстовую дату можно заменить форматированной без акта) |
| Способ хранения при перевозке (CHK-F19) | `transportStorageType` | **Нет** |
| Номер эВСД, дата, статус, назначение груза (CHK-F01–04) | реквизиты самого ВСД | Информационные; в API не передаются при гашении и не проверяются |
| Ранее проведённая ВСЭ (CHK-F24–28) | сведения Меркурия о мероприятиях | Информационные; на гашение не влияют |
| Состояние грузового отделения, совместная перевозка (CHK-F20/21) | результат ветконтроля | Отражаются в `deliveryFacts/vetInspection/result` (CORRESPONDS/MISMATCH), а не в акте |

## 3. Чек-лист: что делает система по несоответствиям

Для каждой отмеченной ветврачом строки «Не соответствует» система классифицирует несоответствие по разделу 2 и далее:

1. **Все несоответствия — из «белого списка»** (ТТН, номер ТС/прицепа, вес/количество/маркировка, срок годности, товарная позиция 4-го уровня):
   - Полное гашение — доступно. Система собирает `discrepancyReport` из фактических значений CHK-F30 (причина несоответствия), объём в допуске 5%.
   - Частичное гашение — доступно. Проверка: принятый + возвращаемый объём = объём ВСД (допуск 5%).
   - Полный возврат — доступен.
2. **Есть несоответствие вне «белого списка»** (отправитель, получатель, производитель, дата выработки, способ хранения, уровень 1–3 справочника продукции):
   - Полное гашение — **блокируется** с пояснением, какие поля запрещают его по API (пример из постановки вопроса: изменённый получатель). Система предлагает ветврачу частичное гашение или полный возврат; выбор — за врачом.
   - Частичное гашение — блокируется по той же причине; альтернативы те же.
   - Полный возврат — доступен всегда.
3. **Несоответствие только в информационных полях** (CHK-F01–04, CHK-F24–28): ни на один метод не влияет — выбор метода полностью за врачом. Это поля «из Меркурия без редактирования» по каталогу; кнопки сверки для них в макете — расхождение с каталогом v1.5 (см. раздел 5).
4. **Вес/количество сверх бизнес-порога ±10%** (D-72/73): система предлагает создать возвратный ВСД; врач может отклонить предложение и выбрать любой из трёх методов, но при полном/частичном гашении объёмное расхождение сверх 5% потребует акта о несоответствии — он формируется автоматически из фактических значений.
5. **Несоответствие только в CHK-F20/21** (состояние грузового отделения, совместная перевозка): влияние — на `vetInspection/result`, а не на акт; все три метода доступны, решение за врачом. При `MISMATCH` по ветконтролю полное/частичное гашение с актом остаётся возможным по API.
6. **Импортный ВСД** (в нашей системе не основной сценарий, но ограничение): через шлюз возможно только полное гашение, без возврата и частичного гашения.

## 4. Правила интерфейса (сохранение выбора за врачом)

- Врач выбирает метод (полное гашение / частичное гашение / полный возврат) свободно; система не выбирает за него и не меняет выбор автоматически (соответствует D-74).
- Блокировка — только по технической невозможности: выбран «полный» или «частичный» метод, а есть несоответствие вне белого списка. В сообщении перечисляются конкретные поля и допустимые альтернативы.
- При частичном гашении система проверяет арифметику: принятый объём + возвратный объём = объём ВСД в допуске 5%; расхождение сверх допуска требует акта — система не отправляет запрос без него и не считает его успехом (PDR-006: неподтверждённый ответ Меркурия — не успех).
- Фактические значения CHK-F30 сохраняются раздельно с исходными и идут в `delivery/consignment` / `discrepancyReport` без перезаписи данных исходного ВСД (PDR-005).

## 5. Замечание к макету evsd-check-usmanov

- Строкам «Номер эВСД», «Дата оформления», «Статус эВСД», «Назначение груза» (CHK-F01–04) и всем полям блока «Ранее проведённая ВСЭ» (CHK-F24–28) даны кнопки «Соответствует/Не соответствует» с вводом фактического значения. Каталог v1.5 относит их к информационным (только просмотр). Для чек-листа это безвредно (на выбор метода не влияет), но макет расходится с каталогом и, вероятно, вводит врача в заблуждение. Требует решения: убрать отметки или изменить каталог.
- Бизнес-порог веса ±10% (D-72) уже API-допуска ±5%; в будущем надо уточнить, всегда ли врача нужно предупреждать о диапазоне 5–10%, где акт обязателен, а предложение возврата ещё не показывается.

## 6. Причина несоответствия (discrepancyReport)

Структура акта по API (`merc:discrepancyReport`): `issueSeries`, `issueNumber`, `issueDate` — необязательные реквизиты бумажного акта; электронный номер генерирует Меркурий; `reason/name` (строка) и `description` (строка) — обязательно хотя бы одно из двух. **Справочника причин в API нет** — причина передаётся свободным текстом; словарь задаём сами в интерфейсе.

Предлагаемый словарь (по «белому списку» допустимых расхождений): Недостача (объём в меньшую сторону); Излишек (объём в большую сторону); Расхождение по количеству мест/частей; Несоответствие товарной позиции; Повреждение маркировки; Истёкший срок годности; Изменение транспортного средства; Изменение товарно-транспортной накладной; Другая причина (текстовый ввод, идёт в `reason/name`).

Поле «Причина несоответствия» добавлять для строк, расхождение по которым уходит в акт: CHK-F12 (количество), CHK-F13 (вес), CHK-F15 (срок годности), CHK-F17/F18 (номер ТС/прицепа), CHK-F22 (ТТН), CHK-F09/F10 (только товарная позиция 4-го уровня). Для полей, блокирующих полное/частичное гашение (CHK-F05–08, F11, F14, F19), и информационных (CHK-F01–04, F24–28) поле причины не нужно: акт не передаётся (`RETURN_ALL`) либо расхождение уходит в `vetInspection` (CHK-F20/21).

## 7. Открытые вопросы

- Уточнить у техподдержки ВетИС, распространяется ли запрет «вне белого списка» на частичное гашение при отсутствии иных расхождений объёма (документ формулирует список одинаково для сценариев 1.2.1 и 1.2.2, но явно ошибка-ответе не перечисляет код).
- Проверить на живом шлюзе поведение при расхождении `productItem` 1–3 уровня vs 4-го уровня для наших видов продукции (говядина/свинина/баранина).
- Решить вопрос разметки информационных полей в макете (раздел 5).
