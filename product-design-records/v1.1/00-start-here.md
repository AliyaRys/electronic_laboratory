## Актуальные правила

- Предметный объём — мясо и продукты убоя, поступления из входящих эВСД. Лаборатория № 1 Казани — исходный пилот; административный доступ расширен на несколько назначенных лабораторий.
- Для поступления с прежней ВСЭ врач выбирает необходимость повторной ВСЭ. Если она требуется, после гашения открывается создание собственной ВСЭ; если не требуется — сохраняется ветка заключения по применимому внешнему основанию. Без прежней ВСЭ поле отсутствует, местная ВСЭ нужна в любом случае.
- Повторная ВСЭ при приёмке отличается от повторного ветеринарного осмотра принятой партии по обращению владельца. Последний процесс сохраняется отдельно.
- Исходящие транспортные ВСД по итогам ВСЭ врач оформляет в веб-интерфейсе Меркурия. В нашей системе после сохранения — карточка ВСЭ без окна создания этих документов. Возвраты и отказ при приёмке остаются в нашей системе через API Меркурия.
- Заключение о реализации выдаётся только на пригодные части. Для двух пригодных и одной непригодной туши доступен документ на две; на непригодную заключения нет. Если пригодных частей нет — скачивание/печать такого заключения недоступны.
- Администратор видит все рабочие разделы доступной лаборатории без создания/редактирования/удаления рабочих записей и без внешних ветеринарных действий. Справочники он редактирует и удаляет. В поступлениях/журнале выбирается одна доступная лаборатория.
- Стоимость исследований можно массово применить к выбранным или всем доступным администратору лабораториям. Тарифы остаются раздельными, постоянного наследования нет. Старые сохранённые расчёты не пересчитываются.

## Что сохраняется из v1.0

Две роли; простые пять прав врача; доступ к записям коллег; одна партия по входящему эВСД и одна местная ВСЭ принятого состава; существующая маркировка, общие признаки головы/органов. Ручной уникальный номер среди существующих местных ВСЭ лаборатории без годового сброса, освобождаемый после удаления. Исправления без версий и каскад удаления осмотров/заключения без архива ВСЭ.

Отклонение от нормы предупреждает и оставляет итог врачу; обязательные результаты этим не отменяются. Первичное исследование по исследованным тушам, показатель повторного осмотра за партию; сохранённые суммы и оценки защищены от смены справочников. Смешанный итог и поздний вывоз не блокируют документ на пригодных.

Недостача 120→100 кг — приём 100 с актом, без возврата отсутствующих 20. Излишек и реальные возвраты требуют проверки ВетИС. При неудачной предусмотренной API-отправке врач работает вручную, без каталога ошибок и автоматического восстановления. Местное завершение по известному поступлению допускается до подтверждённого гашения; неподтверждённый успех не выдумывается.

Бумажная подпись/клеймо заключения, без Max и встроенной ЭП. Восстановление доступа через администратора. Молочный бэкенд, ручные поступления по бумаге, склад/продажи, касса, отдельный модуль проб, старое ТЗ и новые роли не добавлены.

## Приоритет и статус

Решения D-49–57 уточняют затронутые D/PDR v1.0; актуальный текст — документ 02. Аудит и исторические ответы не отменяют новые правила. Вопросы MEET не являются принятыми требованиями. Архитектуру и технические механизмы продуктовые записи не выбирают.

Исходный архив «vse-product-foundation-v1.0.zip» сохраняется без изменения. Файлы в «Функциональные требования», их исходники и архив «ФТ-v1.0.zip» не обновляются до встречи с экспертами по D-57. Изменённые области старых ФТ нельзя считать актуальными для v1.1.

Официальный запуск по-прежнему зависит от реальных данных ВетИС, проверенных методик/тарифов, формы и организационного регламента. Пригодность местного электронного журнала к официальной замене бумаги не подтверждена самим выпуском PDR.
