# 07. Сквозное поведение

Эти правила применяются ко всем FT, включая экспорт, отчёты и учёт проб. R-03/04/08 являются конкретизацией наблюдаемого поведения; архитектурный механизм выбирается отдельно.

### FT-COM-01. Поиск, фильтры и страницы

**Основание:** PDR-019; прежний FT-COM-01; R-03.

**Требование:** Поиск без регистра и крайних пробелов по владельцу/предприятию/номеру эВСД; журнал также по номеру ВСЭ/клейму. Фильтры сочетаются через И и ограничены текущей областью. Даты включают границы в Europe/Moscow; начало после конца — ошибка. По умолчанию новые первыми; одинаковые даты имеют устойчивый порядок. Рабочие и административные списки по 20 записей (R-03). Новый фильтр сбрасывает страницу; устаревший ответ не затирает новый.

**Приёмка:** Поиск чужой лаборатории не раскрывает её; последняя удалённая строка страницы переводит на существующую страницу.

### FT-COM-02. Возврат и связность

**Основание:** PDR-004/019; R-03.

**Требование:** Переходы список → карточка/сверка/ВСЭ → назад сохраняют поиск, фильтры, страницу и контекст. Все ссылки используют идентичность выбранной записи. Недоступные старые маршруты не подставляют демонстрационную запись. Прямое открытие отсутствующего объекта показывает «Не найдено» с доступным выходом.

**Приёмка:** Вторая страница после возврата остаётся второй, открывается та же партия, чужие реквизиты не подставлены.

### FT-COM-03. Несохранённые изменения

**Основание:** Прежний FT-COM-03; R-08.

**Требование:** Уход/отмена/смена контекста при изменённой форме требуют выбора продолжить заполнение или выйти без сохранения. Подтверждённый уход не сохраняет данные скрыто. Ошибка сохранения оставляет введённое доступным при сохранённом праве. Автосохранение не обещается; сохранение черновика ВСЭ исключено O-09. Сохранение начатой сверки остаётся отдельным действием.

**Приёмка:** После сетевой ошибки причина и исследования остаются; уход с чистой формы не вызывает лишнего предупреждения.

### FT-COM-04. Числа, даты и текст

**Основание:** Каталог 08 v1.9; R-04/08.

**Требование:** Числовые поля принимают корректную десятичную запись, для русской запятой/точки применяется единая нормализация. Текст abc, бесконечность и неполная запись не превращаются в числа; отрицательные массы запрещены. Количество сохраняется с точностью единицы Меркурия, без округления до целого без основания. Пробелы не считаются обязательным текстом. Даты валидны, отображаются ДД.ММ.ГГГГ, время ДД.ММ.ГГГГ ЧЧ:ММ. Клеймо и внешние номера не теряют ведущие нули. Точности масс/ограничения внешних текстов — INPUT-01/02.

**Приёмка:** −1 не превращается в 1, пустое не становится 0, номер 001 сохраняет ведущие нули. Сервер повторяет проверки формы.

### FT-COM-05. Согласованное сохранение и повтор

**Основание:** PDR-014/015/020; R-08.

**Требование:** Местные изменения применяются целиком либо не применяются. Итог, исследования, расчёт, статус и регистрация отбора не расходятся. Повторное действие не создаёт дубликаты ВСЭ/отбора/отчёта/списания. При неизвестном исходе сначала проверяется факт, затем допускается безопасный повтор. Внешняя операция имеет собственное подтверждение.

**Приёмка:** Потеря ответа после сохранения ожидания не даёт две пробы; после формирования отчёта повтор не сохраняет второй снимок.

### FT-COM-06. Конкурирующее изменение

**Основание:** Прежний FT-COM-06; R-08.

**Требование:** Устаревшее сохранение/удаление отклоняется с понятным конфликтом и переходом к актуальным данным; медицинские результаты автоматически не сливаются. Запись, удалённая другим пользователем, не восстанавливается старой формой. Срок действия/роль повторно проверяются при фиксации.

**Приёмка:** А сохранил итог, Б не затирает его своей старой вкладкой. Остаток вырос — старый диалог утилизации не списывает другой вес.

### FT-COM-07. Честные состояния и ошибки

**Основание:** PDR-020; прежний FT-COM-07; R-08.

**Требование:** Различаются загрузка, пустой набор, нет совпадений, нет доступа, блокировка, не найдено/удалено, ошибка и неизвестный исход. Ошибка не рисует успешный пустой список/зелёный документ. Доступны безопасный повтор чтения и объяснение следующего действия. Внешний/внутренний диагностический код не заменяет понятное сообщение.

**Приёмка:** Сбой отчётов не показывает «Отчётов нет»; ошибка экспорта не создаёт пустой файл.

### FT-COM-08. Долговременное сохранение и безопасность текста

**Основание:** PDR-001/020; R-08.

**Требование:** Подтверждённые записи доступны после обновления, выхода/входа и другому разрешённому сеансу. localStorage демо не считается промышленным хранением. Введённый текст выводится как данные, секреты не входят в документы/ошибки/историю. Отсутствие доступа не допускает предварительное раскрытие данных.

**Приёмка:** Сохранённая ВСЭ видна коллеге, очистка браузера не удаляет её; текст с HTML не исполняется.

### FT-COM-09. Доступность и узкие экраны

**Основание:** AGENTS.md; UX-CONTRACT.md; R-08.

**Требование:** Русский интерфейс, видимый фокус, имена полей/кнопок, связанные ошибки и понятные состояния. Клавиатурой доступны все действия, меню закрываются Escape, диалоги удерживают фокус и возвращают его инициатору. Опасное подтверждение начинает с безопасного действия. Проверка на 1440/1024/768/390 px: длинные значения и действия доступны, горизонтальная прокрутка только внутри таблицы при необходимости. Цвет не единственный носитель смысла.

**Приёмка:** Завершить сверку, открыть меню, отменить удаление и прочитать ошибку можно клавиатурой; длинное имя доступно без hover-only подсказки.

### FT-COM-10. Переиспользование интерфейса и предел прототипов

**Основание:** AGENTS.md; STORYBOOK.md.

**Требование:** Существующий HTML/обычный JS и общие компоненты сохраняются при переносе. Один код используется страницами и stories; иконки разделов и шапка принадлежат общему реестру. Значимые обычные/ошибочные/загрузочные/длинные/узкие состояния представлены в каталоге. Реальное поведение проверяется на экране, сборка каталога его не доказывает.

**Приёмка:** При последующих изменениях Storybook выполнить build-storybook, при авторизации также test:ui; tmp не становится обязательной зависимостью. Этот выпуск меняет только документацию.
