# 09. Отчёты

Раздел объединяет учёт проб, операционные показатели и регламентированную форму 5-вет. По O-05 врач видит только учёт проб; заведующий — все отчёты своей лаборатории. Аналитик читает доступные данные и формирует отчёты по одной выбранной лаборатории Татарстана, не регистрируя лабораторные физические операции. Администратор не видит раздел. Старый путь admin_makets не является правом администратора.

## Алгоритм формы 5-вет

Отбор: лаборатория совпадает, местная ВСЭ завершена, не удалена, первое время завершения попадает в выбранный календарный диапазон Europe/Moscow: `[дата начала 00:00; дата окончания + 1 день 00:00)`, обе границы включительно. Решение владельца от 2026-11-18: MVP допускает произвольный диапазон дат (в том числе текущий), а не только завершённое полугодие. Ярмарочные и внутренние партии входят; несохранённые формы, ожидание и прежние внешние ВСЭ без местной не входят. Исправление завершённой карточки не меняет период первого завершения (R-04).

| Строка | Вклад одной отобранной ВСЭ |
| --- | --- |
| 166 | 1, независимо от количества туш/исследований |
| 167 | +1 за выполненную бактериоскопию и отдельно +1 за микроскопию |
| 168 | +1 за выполненную трихинеллоскопию |
| 169 | По +1 за выполненные pH, пероксидазу, реакцию с сернокислой медью |
| 170 | +1 за дозометрическое исследование с двумя показателями, а не +2 |
| 171 | По +1 за пробу варки, люминесцентный анализ, температуру в толще мышц |
| 172 | +1 за отправку в аккредитованную лабораторию после ответа и завершения ВСЭ |
| 240 | Принятый вес партии / 1000, только направление «На уничтожение» |
| 241 | Часть 240, классифицированная как мясо |
| 242 | Часть 240, классифицированная как субпродукты |

Органолептика, идентификация, перечни заразных болезней и свободные причины не увеличивают строки 167–172 сами по себе. Находка трихинеллёза не дублирует выполненную трихинеллоскопию. Строка 166 не обязана равняться сумме 167–171. Утилизация проб не относится к 240–242.

**Строка 210 «Незаразные болезни» (решение владельца от 2026-11-18, owner decision `product-design-records/owner-decision-2026-11-18-5vet-full-section-iii.md`):** каждая заполненная строка перечня незаразных находок одной завершённой ВСЭ считается отдельным случаем: строка 210 += число сохранённых строк `findings_snapshot["noncontagious"]` новейшей ревизии карточки (три заболевания в одной ВСЭ дают +3; одинаковые названия не дедуплицируются; инвазионные находки и строки 173/209 не рассчитываются). Отбор совпадает со строкой 166: завершённые карточки периода, новейшая ревизия, ярмарочные и внутренние входят; карточка без незаразных находок даёт честный ноль 0.

Колонки формы: крупный рогатый скот, яки, буйволы; свиньи; овцы, козы; кролики, нутрии; птица — куры и другие виды (две отдельные колонки под общей группой «Птица», никогда не объединяются); рыба; другие виды животных. Наличие колонки не расширяет мясной MVP на рыбу/птицу. Конкретные идентификаторы видов, животное и мясо/субпродукты задаёт INPUT-05. Автоматически считаются только 166–172, 210 и 240–242. Полный печатный каталог — ровно 47 строк раздела III (166–172, 173–235, 240–242) с точными кодами и названиями из образца владельца; он один на сервере, UI, PDF и XLSX. Ячейку строки, которую система не рассчитывает, нельзя заполнять нулём, прочерком или текстом «Не рассчитывается»: в JSON/UI/PDF/XLSX она остаётся пустой (`null`), а рассчитанный ноль автоматической строки виден как `0`.

### FT-RPT-01. Доступ и состав раздела

**Основание:** PDR-003/016/017; O-05; SC-009/076.

**Требование:** Врач открывает раздел «Отчёты» только с учётом проб. Заведующий видит учёт проб, операционные показатели и 5-вет своей лаборатории. Аналитик формирует отчёты и читает доступные лаборатории. Все списки/снимки/выгрузки проверяют доступ; администратору запрещено даже прямым запросом.

**Приёмка:** Врач не открывает 5-вет по известному URL, администратор — отчётный снимок. Заведующий не формирует по чужой лаборатории.

### FT-RPT-02. Операционные показатели

**Основание:** PDR-004/016; SC-013/014/076–079; R-09.

**Требование:** За выбранный период и лабораторию показываются сохранённые ВСЭ (число реально сохранённых карточек данной лаборатории, созданных в периоде, включая WAITING и COMPLETED, по календарю Europe/Moscow), выполненные идентификации продукции и осмотры транспорта. Каждая действительно выполненная и сохранённая услуга даёт одну единицу своего показателя независимо от тарифного множителя. Полный возврат без услуги её не добавляет. Для услуг используется время завершения соответствующего факта, не дата создания ВСЭ (R-09). Остатки проб показываются только на «Учёте проб» и не входят в операционный отчёт.

**Приёмка:** Одна сверка с двумя оказанными услугами: +1 идентификация, +1 транспорт. Отсутствие оказанной услуги даёт 0 по ней. Сохранённые ВСЭ считаются простым подсчётом карточек без двойного счёта.

### FT-RPT-03. Создание формы 5-вет

**Основание:** PDR-017; SC-080; макеты отчётов; R-09.

**Требование:** Выбираются единственный тип «5-вет, раздел III», одна доступная лаборатория и календарный диапазон дат (обе даты обязательны, дата начала ≤ даты окончания; текущий и будущий диапазон разрешены — при отсутствии завершённых источников формирование блокируется с объяснением). По сочетанию тип/лаборатория/диапазон существует максимум один сохранённый отчёт; перекрывающиеся, но не совпадающие диапазоны разрешены. Нет ручного редактирования расчётных ячеек или долговременного черновика.

**Приёмка:** Отчёт формируется и сохраняется за текущий незавершённый диапазон. Конкурирующее сохранение точного дубля отклонено; перекрывающийся диапазон сохраняется.

### FT-RPT-04. Проверяемый расчёт и классификация

**Основание:** PDR-017; SC-081–088.

**Требование:** Матрица считается по таблице выше и сохранённой классификации. Неподдержанное/неоднозначное соответствие не распределяется по похожему названию; формирование требует исправить конфигурацию и не выдаёт частичный успешный отчёт. Вес суммируется до итогового отображаемого округления, кг переводятся в тонны без округления отдельных партий; точность официальной формы — INPUT-04.

**Приёмка:** Одна ВСЭ с бактериоскопией, микроскопией, pH, пероксидазой и температурой даёт 166:+1, 167:+2, 169:+2, 171:+1. Уничтоженные 250 кг мяса дают 240:+0,25 т, 241:+0,25 т.

### FT-RPT-05. Предварительный снимок и сохранение без кодов

**Основание:** PDR-017; макеты отчётов; R-09; решение владельца от 2026-11-18.

**Требование:** Параметры — два постоянных поля дат («С даты», «По дату») и одна кнопка «Применить», которая применяет диапазон и запрашивает предварительный расчёт одним действием; отдельного popover и второй кнопки на странице нет. Во время запроса кнопка показывает «Формируем…» и не создаёт повторный запрос; изменение любого поля после успешного расчёта помечает его устаревшим и блокирует сохранение до нового «Применить»; ошибка сети не очищает введённые даты. «Применить» фиксирует предварительный набор источников, полную матрицу 47×8, лабораторию/адрес и период. Семь организационных кодов (ОКУД, ОКПО, ОКВЭД, ОКТМО, ОКОГУ, ОКОПФ, ОКФС) отменены решением владельца от 2026-11-18: они не вводятся, не показываются и не экспортируются; запрос сохранения содержит только подписанный предварительный снимок.

**Приёмка:** Сохранение работает без ввода каких-либо кодов; недопустимый/обратный диапазон не отправляет запрос; изменение дат после расчёта блокирует сохранение до нового «Применить»; ошибка сети не теряет снимок/параметры.

### FT-RPT-06. Неизменяемый сохранённый отчёт

**Основание:** PDR-014/017; SC-070.

**Требование:** «Сохранить» сохраняет именно показанный снимок: лабораторию/адрес, период, время формирования, автора, матрицу, число и идентичности источников, версию правил/соответствий и точность (R-09). Поздние исправления/удаления ВСЭ и изменения справочников его не пересчитывают. После успеха открывается просмотр без редактирования.

**Приёмка:** Удалить одну исходную ВСЭ после формирования: сохранённая матрица и выгрузка прежние; новый предварительный расчёт без неё.

### FT-RPT-07. Список и просмотр отчётов

**Основание:** Макеты отчётов; R-03/09.

**Требование:** Список: период (ДД.ММ.ГГГГ — ДД.ММ.ГГГГ), лаборатория, число ВСЭ, время формирования, действия. Поиск по лаборатории и периоду, сортировка, 20 строк и возврат с контекстом. В действиях просмотр, Excel, PDF, печать, удаление. Меню не активирует переход строки; строка доступна как ссылка клавиатурой. Просмотр показывает упрощённую шапку отчёта (решение владельца от 2026-11-18): название «5-вет, раздел III», только дату создания, период и лабораторию в Europe/Moscow по серверному времени; до сохранения — «Дата формирования» по времени подписанного расчёта. Служебные данные (источники в снимке, версии, подпись, семь кодов, формальная полугодовая шапка) не показываются, но хранятся для аудита. Полная таблица — одна печатная таблица раздела III: 47 строк, 10 физических колонок с двухуровневой шапкой («Птица» над «куры»/«другие виды» и номера колонок 1–10), код строки не переносится.

**Приёмка:** На 25 отчётах работают вторая страница и возврат; удалённый в другой вкладке отчёт показывает «Не найден».

### FT-RPT-08. Экспорт и печать отчёта

**Основание:** Макеты отчётов; PDR-017; R-09; INPUT-04.

**Требование:** Excel/PDF/печать используют сохранённый снимок, не пересчитывают текущие карточки. Экспорт содержит упрощённую шапку (название отчёта, дату создания, точный выбранный период, лабораторию) и полную матрицу раздела III (47 строк, восемь отдельных колонок животных, двухуровневая шапка «Птица») без интерфейсной сводки, семи кодов и формальной полугодовой шапки; маркировка «Предварительная форма» сохраняется, пока форма official=false. PDF — A4 landscape с повторяющейся шапкой таблицы. Числа Excel остаются числами (рассчитанный ноль — числом 0), нерассчитываемые ячейки остаются действительно пустыми, ничего не выводится как «Не рассчитывается». Заголовки повторяются при печати, колонки не обрезаются. Имя: `5-вет_раздел-III_<лаборатория>_<ГГГГ-ММ-ДД>_<ГГГГ-ММ-ДД>` с безопасными символами.

**Приёмка:** Сопоставить матрицу экрана, xlsx, PDF и печати после изменения источника: все равны сохранённому снимку.

### FT-RPT-08a. Экспорт «Учёта проб» (DR49, 2026-11-18)

**Основание:** DR49 §7–10; O-15; API-06; DATA-03.

**Требование:** Экспорт «Учёта проб» строит PDF и XLSX на сервере из согласованного read-snapshot в момент нажатия: PDF — `GET /api/v1/samples/accounting/export.pdf`, XLSX — `GET /api/v1/samples/accounting/export.xlsx` (query: `laboratory_id`, `date_from`/`date_to` optional). Файл содержит текущие live-остатки лаборатории (не зависят от периода) и ПОЛНУЮ историю утилизаций применённого периода — экранная пагинация никогда не ограничивает файл; остатки и история берутся из одного REPEATABLE READ read-only снимка и не противоречат друг другу. В файлах нет технических GUID продукции, actor_id и внутренних идентификаторов; названия и ФИО разрешаются тем же read model, что и экран («Данные не найдены» при отсутствии). Доступ — только у пользователя с существующим полномочием `sample:read` выбранной лаборатории (ADMIN и чужая лаборатория запрещены; экспорт не расширяет доступ); CSRF и Idempotency-Key для GET не требуются. `date_from > date_to` — 422 с русским текстом до рендера; сбой рендера — 503 RENDERER_UNAVAILABLE без частичного файла; ответы `Cache-Control: no-store`. PDF: A4, заголовки таблиц повторяются, footer «Сформировано … (МСК)»/«Страница N из M». XLSX: ровно два листа «Остатки проб» и «История утилизаций», массы числами, даты — настоящими Excel-датами, номера — текстом с ведущими нулями, значения `=`/`+`/`−`/`@` — quotePrefix, не формулы. Имена файлов: `Учёт_проб_<лаборатория>_<from|все>_<to|все>.pdf/.xlsx`.

**Приёмка:** При пагинированной (>20 строк) истории в файл попадают все строки периода; при пустых остатках/истории файл корректен и содержит понятное пустое состояние; пользователь без `sample:read` получает отказ без файла.

### FT-RPT-09. Удаление сохранённого отчёта

**Основание:** Макеты отчётов; R-09.

**Требование:** Заведующий/аналитик в своей отчётной области удаляют снимок после подтверждения лаборатории/периода и отсутствия восстановления. Карточки и физические пробы не меняются, скачанные файлы не отзываются. Период снова доступен; повторно сформированный отчёт использует текущие источники и правила.

**Приёмка:** После удаления последней строки страницы корректируются счётчик/страница; новый отчёт по периоду не наследует старую матрицу.
