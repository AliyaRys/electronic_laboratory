# Уточнения владельца

Эти решения получены в текущем чате после PRD 1.9 и имеют приоритет в затронутых случаях. Исходники PRD оставлены неизменными.

| ID | Решение | Последствие |
| --- | --- | --- |
| O-01 | «Только весь остаток, вес подставляется из учёта» | Частичной утилизации нет. Вес берётся из актуального остатка выбранного вида продукции и не редактируется вручную |
| O-02 | «Разрешить удаление ВСЭ, физическую пробу и утилизацию сохранить отдельно» | Удаление карточки не вычитает физически отобранную пробу и не отменяет утилизацию. Учёт проб имеет самостоятельную идентичность, без восстановления удалённой ВСЭ |
| O-03 | «В день создания все поля; позднее только итог» | Ожидающую карточку можно полностью исправлять в день создания, затем — только VSE-F35–37. Исключение не продлевает удаление |
| O-04 | «Использовать прежнюю пробу; новый отбор отмечать отдельно» | Пересоздание ВСЭ по партии не удваивает остаток. Новый фактический отбор — отдельное явное событие |
| O-05 | «Нет, дадим доступ к разделу "Отчеты", но в этом разделе вет врачам будет доступен учет проб, а заведующему все отчеты» | Раздел «Отчёты» общий. Ветврач видит в нём только учёт проб своей области; заведующий также операционные показатели и форму 5-вет своей лаборатории. Администратор доступа не получает. Аналитик сохраняет права PRD 1.9 |
| O-06 | Сохранить удаление пользователей администратору, ожидаемых поступлений врачу/заведующему, справочников их редакторам | С учётом новой роли и области; пять старых флажков не возвращаются как модель доступа |
| O-07 | Исправления и отмена утилизации в MVP не нужны | Сохранённая утилизация неизменяема; сценарий обратного списания отсутствует |
| O-08 | Администратор может назначать все четыре роли, только в пределах предоставленных полномочий | Нельзя расширить собственную территорию/право выдачи роли или автоматически получить доступ к рабочим данным |
| O-09 | «Убрать сохраняемые черновики: остаются завершение и ожидание результатов» | Незавершённая форма не создаёт постоянную ВСЭ, не резервирует партию/номер и не блокирует работу на следующий день |
| O-10 · 07.11.2026 | Локально хранить полный справочник второго уровня `productType=1` из `GetProductByTypeList`; названия входящих ВСД разрешать по GUID без SOAP-запроса при каждом чтении. Трихинеллоскопия обязательна для четырёх точных категорий: свинина, конина, субпродукты и жиры свиные, субпродукты и жиры конские | Таблица `mercury_product_guid_lvl_2` разделяется по контуру, хранит GUID, текущий UUID и название всех 28 записей pilot-снимка. UI не показывает сырой GUID вместо названия. Условная обязательность VSE-F21 определяется только четырьмя утверждёнными GUID, не сравнением текста |
| O-11 · 08.11.2026, уточнено 08.11.2026 | Из-за неработающего получения входящих ВСД в тестовом контуре чтение подключается сразу к production. Каждые 15 минут система обновляет входящие оформленные эВСД Агропромышленного парка и человекочитаемо отображает идентификаторы через локальные справочники. Гашение должно быть полностью проработано, но является юридически значимым и не тестируется на production | Production-интеграция текущего выпуска строго read-only; `VETIS_WRITE_ENABLED=false`. Write полностью реализуется и проверяется на fixtures/симуляторе: XML строится из закреплённой версии входящего документа и сверки. До отдельного решения владельца реальный submit требует внешнего ограниченного разрешения на конкретный UUID/решение/срок и явного подтверждения пользователя; тест, администратор или один feature flag не могут его включить |
| O-12 · 09.11.2026 | Подключение всё же выполняется к тестовому профилю ВУ. Выданы локальные credentials, успешный пример получения входящих эВСД Агропромышленного парка и шесть XML-сценариев гашения. В мясной MVP попадают только ответы с `productType=1`. Человекочитаемые `name` берутся из самого эВСД, общий справочник продукции для UI не нужен. Ни при каких обстоятельствах сейчас не выполнять живое гашение: созданные ветеринарами эВСД должны остаться доступными | O-12 заменяет контурную часть O-11 и требование O-10 использовать общий справочник как источник UI-названия. V01/V02 проверяют чтение тестового контура; фильтр `productType=1` применяется локально. GUID/UUID и source `name` сохраняются вместе по уровням. Четыре GUID трихинеллоскопии остаются отдельным policy mapping. Все шесть write-сценариев используются только как обезличенные fixtures/preview; `ProcessIncomingConsignment` не вызывается без нового явного указания владельца |
| O-13 · 09.11.2026 | Запрет живого гашения относится к самостоятельным действиям ИИ-агентов и тестированию, а не к функциональности продукта. Возможность гашения должна быть полностью реализована: рабочая кнопка, XML, реальный submit, poll/reconcile и состояния результата. Агент не должен гасить созданный ветеринарами эВСД, чтобы проверить свой код | W01–W03 обязаны реализовать production-код external transport и enabled-state UI, а не постоянную заглушку/503/preview-only. Автотесты и приёмка используют fixtures и transport spy. `VETIS_WRITE_ENABLED` по умолчанию false и не включается агентом; после решения владельца оператор включает capability, а уполномоченный пользователь выполняет гашение с явным подтверждением. Поштучное внешнее owner authorization не требуется |

O-02 уточняет PDR-014: исключение удалённой ВСЭ из расчётов не уничтожает самостоятельный физический факт пробы. O-03 уточняет ограничения каталога 08 §1.6. O-05 меняет доступность навигационного раздела для врача, но не даёт ему форму 5-вет. O-10 расширяет D-114/PDR 1.9 с двух мясных категорий на четыре точных категории второго уровня и закрывает часть INPUT-02 о GUID для VSE-F21. O-12 заменяет O-11 в выборе контура и O-10 в источнике отображаемого названия. O-13 требует полностью реализовать внешний write-маршрут, одновременно запрещая агентам подтверждать его пробным гашением.
