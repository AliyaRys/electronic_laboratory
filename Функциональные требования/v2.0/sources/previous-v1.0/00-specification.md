# 00. Основа спецификации

## 1. Назначение и критерий результата

Основной пользователь — ветеринарный врач государственной лаборатории ВСЭ на рынке. Продукт фиксирует факты приёмки и исследований, поддерживает операции Меркурия и подготовку заключений; медицинское решение принимает врач. Цель первой очереди — рабочий электронный учёт вместо бумажного журнала после организационного допуска, а не только демонстрация экранов.

Результат MVP: врач с разрешённым доступом получает входящий эВСД, сверяет реально прибывшую партию, фиксирует приёмку, проводит одну собственную ВСЭ либо использует применимую внешнюю, получает документ только на пригодную продукцию и при обращении владельца сохраняет повторный осмотр. Администратор ведёт доступ сотрудников. Сохранённая информация доступна после повторного входа, одинаково отображается в списках, карточках, расчётах и печатных формах.

## 2. Границы

| Входит в MVP | Не входит |
|---|---|
| Лаборатория № 1 г. Казани; мясо и продукты убоя | Другие лаборатории, молочный бэкенд и другие категории |
| Поступления из полученных входящих транспортных эВСД | Ручное создание поступления по бумаге или одному введённому номеру |
| Сверка, фактическая приёмка, расхождения, предусмотренные внешние операции | Каталог ошибок Меркурия, автоматическое восстановление обмена, диспетчер повторов для врача |
| Собственная ВСЭ по тушам и применение прежней внешней ВСЭ | Новая местная ВСЭ ради копирования внешней; модуль учёта проб |
| Скачивание и печать заключений; подпись на бумаге | Max, встроенная электронная подпись, автоматическое подтверждение вручения |
| Повторные осмотры по обращению владельца и ручной наблюдаемый остаток | Личный кабинет владельца, расписание обязательных осмотров, продажи, складской баланс |
| Расчёт услуг и справочники норм/цен | Касса, платежи, фискализация, бухгалтерия |
| Исправление актуальных данных и удаление ВСЭ | История версий ВСЭ, архив удалённых ВСЭ, восстановление средствами продукта |
| Две роли и пять простых разрешений | Дополнительные роли, согласующие, матрица прав по каждой продукции |
| Административное восстановление местного доступа | Почтовое восстановление, приглашения и активация по ссылке |

Основания: PDR-001–016; D-01–48. Будущая расширяемость не означает включения будущих функций в приёмку MVP.

## 3. Словарь и предметные границы

| Термин | Значение в этом комплекте |
|---|---|
| Поступление / партия | Продукция одного входящего транспортного эВСД. Не объединять разные эВСД в одну партию |
| Документальное количество | Количество и масса в полученном исходном эВСД |
| Доставлено | Физически прибывшая продукция, независимо от решения о приёмке |
| Принято | Фактически допущенный в местный рабочий цикл состав |
| Реальный возврат | Продукция, действительно направляемая обратно; отсутствующий груз возвратом не является |
| Туша / учётная часть | Отдельная уже маркированная туша, полутуша или другая представленная в принятом составе часть. Тип хранится явно; полутуша не превращается автоматически в целую тушу для массы или тарифа |
| Собственная ВСЭ | Одна местная экспертиза всего принятого состава данной партии, с индивидуальными результатами и итогами частей |
| Внешняя ВСЭ | Применимое ранее проведённое исследование другой лаборатории с сохраняемым происхождением; не местная запись ВСЭ |
| Заключение | Производный документ о реализации пригодного состава по собственной ВСЭ или внешнему основанию принятой партии |
| Повторный осмотр | Отдельная запись наблюдения по обращению владельца, связанная с принятой партией и основанием ВСЭ |
| Завершение | Подтверждение полноты местных данных; не подтверждение внешней операции |
| Вывоз | Реальное движение продукции; оформление исходящего документа само по себе его не доказывает |
| Оценка исследования | Соответствие применённой норме; отдельно от окончательного итога врача |

## 4. Логические сущности и связи

Это предметная модель, не схема БД и не перечень сервисов.

| Сущность | Обязательные смысловые связи |
|---|---|
| Сотрудник | Лаборатория; состояние доступа; продукция и права для пользователя; личное внешнее соответствие Меркурия |
| Исходный эВСД | Внешняя идентичность, реквизиты, участники, продукция, внешний статус |
| Сверка/приёмка | Исходный эВСД, фактические данные, принятый/возвращаемый состав, решение, врач, дата |
| Принятая часть | Поступление, имеющаяся маркировка, тип, количество и масса |
| Собственная ВСЭ | Поступление, все принятые части, ручной номер, специалист, результаты, итоги, применённые нормы и расчёт |
| Внешнее основание | Поступление и охваченная продукция, организация, дата, идентификатор, доступный результат |
| Внешняя операция | Поступление либо ВСЭ, тип/назначение, состав и количества, фактический результат/идентификатор при подтверждении |
| Повторный осмотр | Принятое поступление и местная ВСЭ либо внешнее основание, наблюдаемый остаток, результаты, расчёт |
| Справочник | Применимость, исследование/услуга, единица, норма либо цена; сохранённые рабочие записи не зависят от его дальнейшего наличия |
| Административное событие | Пользователь, исполнитель, время, реальные изменения; без секретов |

Связь определяется устойчивой идентичностью, а не совпадением названия хозяйства, номера в интерфейсе или порядком строк. Удалённый и вновь использованный номер ВСЭ не связывает старую и новую запись.

## 5. Состояния и переходы

**Детализация R-02.** В интерфейсе разделить этап поступления, состояние ВСЭ и факт внешнего исполнения.

| Объект | Состояния и переходы |
|---|---|
| Поступление | «Ожидается» → «В работе» при начале сохранённой сверки → «Принято» при завершённом местном решении с положительным составом. При полном отказе — «Отказано», без принятого состава. Неприбытие не переводится в «Принято» |
| Собственная ВСЭ | Ещё не создана → «Черновик» → «Завершена». Редактирование завершённой записи сохраняет завершённость только при выполнении проверок завершения. Удаление убирает запись, заключение и связанные осмотры |
| Внешняя ветка | Принято → основание проверено/недостаточно данных. При достаточном основании доступно заключение без местной ВСЭ |
| Меркурий | «Не отправлено»; «Отправляется»; «Подтверждено»; «Не подтверждено — проверьте в Меркурии». Из последнего в подтверждённое — только после получения внешнего факта. Каталог кодов ошибок не вводится |
| Направление части | Решение врача задано → документ ещё не оформлен → внешний документ подтверждён. Факт вывоза/обработки не выводится из последнего состояния |
| Учётная запись | «Активен» ↔ «Заблокирован»; удаление допустимого обычного пользователя закрывает вход |

«Принятые» — единое имя списка местно принятых партий; слово «Завершена» применяется к ВСЭ. Принятая партия может ещё не иметь завершённой собственной ВСЭ. Отказанные поступления доступны для просмотра в рабочем контексте через отдельный фильтр результата приёмки, без отдельного нового раздела. Внешний неподтверждённый статус виден рядом с местным этапом и не маскируется зелёным общим успехом.

## 6. Инварианты всего MVP

1. Лаборатория, продукция и актуальное право проверяются при чтении и действии. Авторство не ограничивает врача.
2. Один входящий транспортный эВСД соответствует одной партии и максимум одной существующей местной ВСЭ; применимое внешнее основание исключает дублирующую местную ВСЭ.
3. Недоставленные и фактически возвращаемые части не исследуются как принятые. Исходные сведения эВСД сохраняют свой смысл.
4. Лаборатория не становится собственником продукции вследствие приёмки.
5. Числа, массы, внешние идентификаторы, нормы и результаты не подставляются для обхода отсутствующих данных.
6. Отсутствие обязательного результата блокирует завершение. Отклонение полученного результата от нормы только предупреждает.
7. Итог врача по каждой части хранится отдельно от автоматической оценки исследования.
8. Заключение о реализации включает только пригодный состав. Направление на обработку не равно разрешению на свободную реализацию.
9. Местное завершение и печать допустимы до подтверждения гашения известного поступления при сбое Меркурия.
10. Смена текущего справочника не меняет сохранённые суммы и оценки. Их основания воспроизводимы из самой актуальной рабочей записи.
11. Повторный осмотр не переписывает первоначальную ВСЭ/заключение и не вводит отдельный вычисляемый запрет реализации.
12. Удаление ВСЭ не аннулирует внешние документы, не создаёт архив и освобождает ручной номер.

## 7. Статус конкретизации и приоритет

Приоритет: прямые решения D → PDR → согласованные ФТ → явно указанная основа S → макеты как перечень полей. Находки A предотвращают повторение ошибок, но сами не утверждают новые функции. Текущая рабочая копия старше некоторых опубликованных в архиве изменений: её Max, почтовые сценарии и старое ТЗ не отменяют PDR.

Форматы, пагинация, PDF, конфликтное сохранение и другие новые правила с R-xx — предлагаемые решения ФТ, перечисленные в разделе 08. Они делают спецификацию проверяемой; до обзора владельцем не называются уже принятыми. INPUT-01–04 содержат реальные внешние и предметные данные, которых в архиве нет; их отсутствие нельзя исправить уверенной формулировкой. Архитектуру можно прорабатывать с обозначенными границами, официальный запуск — только после закрытия применимых зависимостей.
