# 09. Трассировка и приёмка

## 1. Как использовать проверки

Все карточки FT содержат наблюдаемые критерии. Ни исходные SC, ни таблицы ниже не являются отчётом о выполненных тестах приложения. Источник всех SC/D — [интервью v1.0](sources/03-interview-and-validation.md), PDR — [продуктовые записи](sources/02-product-design-records.md), A — [аудит](sources/01-product-audit.md). В матрицах указаны точные идентификаторы карточек, определения которых находятся в профильных разделах 01–07.

У каждого ФТ приоритет **MVP / обязательно в описанных границах применимости**. Источник «основа» и предлагаемая детализация R сохраняют свой статус до обзора владельцем. Для условного процесса проверка выполняется, когда этот процесс применим; зависимость INPUT не превращает весь отложенный продукт в обязательный объём.

## 6. Дополнительные приёмочные примеры ФТ

Это новые проверки конкретизации R, а не дополнительные ответы интервью. Выполнить их после утверждения соответствующих правил.

| ID | Дано → действие → ожидается |
|---|---|
| AC-01 | Черновик без номера → сохранить → сохранён без заключения; номер 001 при существующем 1 → отказ дублирования по R-01 |
| AC-02 | Два врача начали собственную ВСЭ одной партии → одновременно сохранить → одна существующая ВСЭ, второму понятный конфликт |
| AC-03 | А сохранил правку, Б открыл раньше → Б сохраняет → отказ устаревшего сохранения; Б не затирает А |
| AC-04 | Введена масса 0,0001 кг / −1 / 12abc → завершить → ошибка у поля; исходный вес не подставлен |
| AC-05 | Норма с включённой/исключённой границей → значения ниже/на/выше → оценки соответствуют проверенной методике |
| AC-06 | Старый показатель 4×100, текущий тариф 150 → в старой записи изменить охват на 3 → 300 по закреплённой цене; новый показатель берёт текущую |
| AC-07 | Справочная строка удалена → открыть старую ВСЭ и новую форму → старые сумма/оценка прежние, новой недостаёт настройки |
| AC-08 | Ожидаемый эВСД удалён → обновить тот же неизменённый / изменённый → скрыт / показано новое внешнее изменение по R-08, без внешней мутации |
| AC-09 | Сотрудник с документами → попытка удаления → блокировка как альтернатива; документов не убыло |
| AC-10 | Сброс заблокированного аккаунта → новый пароль → запись остаётся заблокированной, прежние права/продукция сохранены |
| AC-11 | Остаток ноль → сохранить наблюдение → нет проведённых исследований/начислений и выдуманного положительного результата |
| AC-12 | Части 100/110/90 кг, последняя непригодна → файл/печать → только первые две, 210 кг |
| AC-13 | Внешняя ВСЭ неполна → запросить заключение → перечень недостающего, без новой местной ВСЭ/фиктивного результата |
| AC-14 | Подтверждённый исходящий документ, затем местная правка состава → сохранить → внешнее состояние не переписано, видна необходимость сверки |
| AC-15 | 25 записей, поиск и вторая страница → карточка → назад → прежний контекст и корректный счётчик |
| AC-16 | Ширина 390 px, длинный адрес и 30 маркировок → пройти формы и диалог клавиатурой → все данные/действия доступны, фокус возвращён |
| AC-17 | Потерян ответ после местного сохранения или внешней отправки → повтор → сначала проверен факт, нет дубля/вымышленного успеха |
| AC-18 | Приёмка внешней партии → свой повторный осмотр → нет местного первичного начисления, повторный показатель один раз за партию |
| AC-19 | Изменён комментарий старой ВСЭ после смены нормы/цены → сохранить → старые оценки/цены неизменённых показателей прежние |
| AC-20 | Удалена ВСЭ, номер вновь использован → открыть новую → нет старых результатов/осмотров/заключения и старых внешних связей как её собственных |

## 7. Приёмка реализации

1. **Документальная:** владелец проверяет границы и R-01–19, ответственным переданы INPUT/OPS. Это проверка спецификации, не тест продукта.
2. **Предметная:** методист и ответственный за цены утверждают содержимое таблиц; отдельно выполняются границы, единицы и формулы. Тестовые числа не попадают в продуктивные настройки.
3. **Функциональная:** по каждой карточке FT выполняются её критерии, все применимые SC и AC, включая отказы/конфликты/доступ. Отмечаются фактические результаты, а не только факт запуска набора.
4. **Интеграционная:** на согласованном внешнем контуре проверяются INPUT-01 и отсутствие дублирующих операций, личный инициатор и ручной путь D-48. Статическая сборка это не заменяет.
5. **Документная/интерфейсная:** сверяются файл/печать и реальный экран; русский язык, клавиатура, длинные данные и 390 px. При изменении Storybook — сборка; при изменении авторизации — UI-проверки по AGENTS.md. Старые ожидания приглашений не принимаются как требования.
6. **Эксплуатационная:** INPUT-04/OPS-01, контроль резервного восстановления и порядок ручного продолжения при сбоях. Только после подтверждения организацией — официальный переход.

Новая реализация принимается по согласованной редакции ФТ. Если конкретный INPUT выявил невозможность принятого правила, фиксируется адресное изменение; «зелёные тесты» с фиктивным внешним ответом не закрывают такую зависимость.
