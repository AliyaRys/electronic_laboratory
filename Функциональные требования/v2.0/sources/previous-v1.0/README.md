## Формат и применение Superpowers

Использован установленный Superpowers 6.4.2: `using-superpowers`, `brainstorming`, `verification-before-completion`. Его `brainstorming` требует секционную спецификацию, явный scope, понятные границы частей, потоки данных, обработку ошибок, проверку непротиворечивости и обзор владельцем перед переходом к реализации. Отдельного обязательного шаблона функциональных требований с фиксированными полями в прочитанных навыках нет. Поэтому применён формат письменной спецификации с карточками **идентификатор → происхождение → правило → критерии приёмки**, дополненный таблицами полей, состояний и зависимостей. Этот формат является адаптацией процесса Superpowers, а не вымышленным стандартом плагина.

Путь по смыслу архитектурный: набор требований охватывает несколько связанных предметных областей. Текущий результат заканчивается письменной спецификацией. Архитектурные решения, технические контракты, план реализации и разработка следуют отдельными этапами после её проверки. Расположение `ФТ/` задано владельцем вместо стандартного каталога Superpowers.

## Правила для следующего ИИ-агента

1. Читать весь комплект, включая зависимости и исходники. Не извлекать требования только из краткого README.
2. **«База»** в карточке означает подтверждённое PDR поведение либо явно указанную основу репозитория. **«Детализация R-xx»** — конкретизация, предложенная автором ФТ; её нельзя приписывать ответам владельца. Весь выпуск ожидает проверки владельцем.
3. Данные INPUT не считать заполненными. Для каждой зависимости указан результат, ответственный и действие при отсутствии. Нормы, тарифы, сроки, полномочия и внешние идентификаторы не генерировать из примеров.
4. Каждому ADR дать ссылки на конкретные ФТ. Сохранить выбранные владельцем простые права, отсутствие истории ВСЭ, ручной обход неудачной отправки и бумажную подпись.
5. При новом существенном противоречии предложить адресное изменение PDR/ФТ. Не менять продуктовую модель техническим решением.

Для передачи достаточно всей папки `ФТ`: обязательных ссылок на `tmp/` в ней нет. Исходный архив остаётся в корне проекта. Текущий локальный файл старого ТЗ бэкенда сознательно не использован: он исключён D-05, даже если присутствует в этой рабочей копии.
