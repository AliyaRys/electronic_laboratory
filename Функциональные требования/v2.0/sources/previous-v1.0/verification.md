# Проверка комплекта ФТ

**Дата:** 22.10.2026. Проверена документация, а не реализация приложения.

## 1. Происхождение

Источник: `vse-product-foundation-v1.0.zip` из корня проекта. SHA-256 архива:

`abf734ea532de85100f04329b62b17b7bf687ea15b1f9b1e9232e4986ad7ef9e`

В `sources/` сохранены шесть исходных Markdown-файлов. Их содержимое сравнивается непосредственно с записями исходного ZIP по SHA-256; это неизменённые источники, а не новая редакция PDR. Ограничения исходной проверки ВетИС/нормативных источников сохраняются.

Дополнительно просмотрены текущие мясные формы приёмки, создания ВСЭ, повторного осмотра, справочников и журнала, определения направлений, документы администрирования и профиль. Они использованы для конкретизации полей с маркировкой R, без переноса исключённых старого ТЗ, молочного бэкенда, Max и почтового восстановления. Текущий Git HEAD рабочей копии — `0c954ca`; более поздние продуктовые решения взяты из архива, а не отменены устаревшим локальным кодом.

## 3. Содержательный самоконтроль Superpowers

**Фактический результат автоматической проверки 22.10.2026:** 87 уникальных карточек, все обязательные поля присутствуют; ссылки на требования и локальные документы разрешаются; 16/16 PDR, 48/48 D, 47/47 SC, 27/27 A и 19/19 R представлены в реестрах; ошибок проверки не обнаружено. Независимое сравнение SHA-256 дало совпадение всех 6 исходных файлов с ZIP. Автоматическая проверка полноты идентификаторов не доказывает полноту предметного смысла; для него выполнен самоконтроль ниже и предусмотрен обзор владельцем.

Проверены четыре направления `brainstorming`: полнота разделов, внутренняя согласованность, границы MVP, неоднозначность требований. В частности:

- Предупреждение об отклонении не отменяет обязательности получения результата.
- Неподтверждённое гашение не блокирует местное завершение в принятом сценарии сбоя и не показывается успешным.
- Недостача не создаёт физический возврат; излишек не получает выдуманный внешний допуск.
- Внешняя ВСЭ не копируется в местную; осмотр возможен без местной первичной записи.
- Первичная/повторная единицы тарификации различны; изменение текущих настроек не переписывает сохранённые основания.
- Смешанный итог не разрешает всю партию; поздний вывоз не блокирует документ на пригодных.
- Исправление и удаление не порождают скрытую историю ВСЭ; административная история пользователя имеет отдельное назначение.
- Секреты не включаются в историю/документы; сброс пароля не меняет Меркурий и права.
- Недостающие предметные/внешние данные вынесены в конкретные INPUT, предложенные поведения — в R, без присвоения им статуса ответов владельца.

## 4. Что эта проверка не подтверждает

Не выполнялись разработка или тесты функциональности, сборка Storybook, живые операции Меркурия, валидация клинических норм, утверждение реальных цен, пробная печать на принтере и правовой допуск электронного журнала. Продуктовый код и интерфейс этой задачей не менялись; поэтому сборка и UI-тесты не являются проверкой данного документационного изменения.

Ссылки на внешние сайты сохранены как часть происхождения исходного архива; их доступность и актуальность заново не проверялись. Перед финальным ТЗ и официальным запуском требуются результаты раздела 08 и приёмка раздела 09. Наличие полного реестра требований не подменяет эти проверки.
